# 2. 開発の基本とサンプル

[English](../en/2-development-and-samples.md)

dev イメージで起動した実機に、PC からアプリを入れて動かす手順です。前提: [1-実機の準備.md](1-実機の準備.md) が済み、
`ssh root@192.168.7.2` で入れること。コマンドは PC のリポジトリ直下で実行します。

## 実機の中の仕組み (最低限)

- 起動すると `hako-session` が、ユーザー `hako` でキオスク用コンポジタ **cage** を立ち上げ、その中で
  **ランチャー** (`hako-launcher`) を全画面で動かす。縦長のパネルは cage が回すので、アプリからは 1280x960 の横長画面に見える。
- ランチャーは `.app` ファイルの一覧からアプリを起動し、終わるのを待つ。**HOME 長押し**で、動いているアプリを終了させて戻る。
- `.app` を置く場所: パッケージは `/usr/share/hako/apps/`、開発中は `/data/dev/apps/` (タイルに「開発」と出る)。
- アプリは SDL3 (または SDL3 を使うエンジン) で作る。画面は Wayland、音は PipeWire、入力はゲームパッドとタッチ。

```ini
# /data/dev/apps/mygame.app
Name=マイゲーム
Name[en]=My Game
# 実行ファイル
Exec=/data/dev/mygame/mygame
# 引数 (空白区切り、"..." でまとめられる)
Args=--fullscreen
# 作業ディレクトリ (省略時は Exec のディレクトリ)
Dir=/data/dev/mygame
# タイルのアイコン
Icon=icon.png
# 環境変数 (複数行可)
Env=FOO=1
# 並び順
Order=10
```

`#` のコメントは行の先頭にだけ書ける (値の後ろに書くと値の一部になる)。

## 2 つの開発の回し方

### A. ファイルを転送して試す (速い。開発中はこちら)

```bash
rsync -a build/mygame/ root@192.168.7.2:/data/dev/mygame/
scp mygame.app root@192.168.7.2:/data/dev/apps/
ssh root@192.168.7.2 /usr/lib/hako/launch-app mygame     # すぐ起動 (動いているアプリは閉じる)
```

アプリはユーザー `hako` で動くので、`/data/dev/` 以下はそのユーザーが読めるようにしておきます。

### B. パッケージにして入れる (正式な形)

```bash
bash scripts/build-packages.sh mypkg     # packages/mypkg を arm64 でクロスビルド → out/packages/
bash scripts/dev-update.sh mypkg         # PC の apt リポジトリに登録し、ssh のトンネル経由で実機に入れる
```

- パッケージを変えたら `debian/changelog` の版を上げる (上げないと apt が入れ直さない。試すだけなら `--reinstall`)。
- `dev-update.sh` は実機の Wi-Fi が無くても動く (Debian の依存も PC 経由で取る)。
- パッケージの作り方は [3-アプリをまとめる.md](3-アプリをまとめる.md)。

## 確認に使うもの

```bash
# 画面を撮って PC で見る
ssh root@192.168.7.2 'runuser -u hako -- env XDG_RUNTIME_DIR=/run/user/$(id -u hako) WAYLAND_DISPLAY=wayland-0 grim -s 0.5 /tmp/s.png'
scp root@192.168.7.2:/tmp/s.png .

# アプリとランチャーのログ
ssh root@192.168.7.2 'journalctl _UID=$(id -u hako) -f'

# ランチャーに戻す (HOME 長押しと同じ)
ssh root@192.168.7.2 'kill -USR1 $(pgrep -o -x hako-launcher)'

# セッションの設定を一時的に変える (例: ボタンを刻印基準に)。消せば元に戻る
ssh root@192.168.7.2 'echo HAKO_PAD_LAYOUT=label >> /data/dev/session.env; systemctl restart hako-session'
```

リモートデバッグは、実機で `gdbserver :2345 <exe>`、PC で `gdb-multiarch` → `target remote 192.168.7.2:2345`。

## ゲームパッドのボタン

- SDL3 の a/b/x/y は**位置** (下/右/左/上) で、刻印ではない。本機は任天堂配置なので、下のボタン (刻印 B) が a。
- 刻印を表示したいときは `SDL_GetGamepadButtonLabel` を使う (本機は Switch 配置として SDL に伝えてある)。
- `HAKO_PAD_LAYOUT=label` にすると a/b/x/y が刻印どおりになる。代わりに位置を前提にしたアプリ (図を描く、下ボタン = 決定) はずれる。
  既定は `position`。詳しくは [リファレンス.md](リファレンス.md) の「SDL3 とパッド」。
- Start + Select で終了、をサンプルでは共通にしている。HOME 長押しはいつでも効く。

## サンプル

どれも、パッド・タッチ・音・FPS を確かめられるようにしてあります。新しく作るときのひな形にしてください。

| サンプル | 言語 / 描画 | 場所 | 入れ方 |
|---|---|---|---|
| SDL3 サンプル | C / SDL_Renderer | `packages/hako-sdl-hello/` | イメージに入っている (`hako-sdl-hello`) |
| raylib サンプル | C / OpenGL | `packages/hako-raylib-hello/` | イメージに入っている (`hako-raylib-hello`) |
| raylib クラシック | C / OpenGL | `packages/hako-raylib-classics/` | イメージに入っている (`hako-raylib-classics`) |
| LÖVE サンプル | Lua / Vulkan | `samples/love-hello/` | 本体 `hako-love` はイメージに入っている。サンプルは転送する (下記) |
| Siv3D ゲーム集 | C++ / OpenGL | `packages/hako-siv3d-games/` | イメージに入っている (`hako-siv3d-games`) |
| Siv3D | C++ / OpenGL | (siv3d_app から作る。下記リンク) | 転送して `.app` で登録 |
| 吉里吉里Z | TJS / OpenGL | (krkrz_dev の SDL3 版をビルド。下記リンク) | 転送して `.app` で登録 |

### SDL3 サンプル (`hako-sdl-hello`)

リンク: [SDL](https://www.libsdl.org/) / [SDL3 Wiki](https://wiki.libsdl.org/SDL3/) / [GitHub](https://github.com/libsdl-org/SDL)

- C 1 ファイル + Makefile + debian/。一番小さいひな形。ABXY の図・タッチ・音・FPS。
- cage を使わず KMS/DRM に直接描く場合の回転処理 (`--rotate`、`HAKO_ROTATE`) も入っている。

### raylib サンプル (`hako-raylib-hello`)

リンク: [raylib](https://www.raylib.com/) / [cheatsheet](https://www.raylib.com/cheatsheet/cheatsheet.html) / [GitHub](https://github.com/raysan5/raylib)

- raylib 6.2 をサブモジュールで固定し、SDL3 で動く設定で静的に組み込む (`CMakeLists.txt` の `PLATFORM=SDL`)。
- 3D シーン: 左スティックで移動、下ボタンでジャンプ、右スティックでカメラ、L2/R2 でズーム。
- 自分のゲームを raylib で作るときは、このディレクトリを丸ごとコピーして名前を変えるのが早い。

#### raylib クラシック (`hako-raylib-classics`)

raylib の作者による古典ゲーム 12 本 ([raysan5/raylib-games の classics](https://github.com/raysan5/raylib-games/tree/master/classics)、zlib) を、
1 つのアプリにまとめたもの。メニューから選び、パッドとタッチで遊べる。

- 元のソースは `classics/` に手を加えずに置き、`src/games/` のラッパーから取り込む。ラッパーは `src/hk.h` のマクロで
  `main()` の名前を変え、`BeginDrawing()` / `EndDrawing()` をゲームごとのレンダーテクスチャへの描画に、
  キーボード・マウスの問い合わせを `src/hk_input.c` に向ける。
- 入力: 矢印キー = 十字キー / スティック、Space・Enter = A (刻印どおり)、P (一時停止) = START。タッチすると画面に十字キーと A が出る。
  マウスのゲーム (Gorilas、Missile Commander) はタッチがそのままマウスになり、スティックでポインターを動かして A でクリックする。
- START+SELECT / HOME / Esc / 左上の MENU でメニューに戻る。ライセンス (ゲーム、raylib、raylib が組み込む外部ライブラリの告知) はメニューの
  Licenses で読める。raylib の告知文は `packages/hako-raylib-hello/licenses/` にあり、raylib のサブモジュールを更新したら `make-licenses.py` で作り直す。
- raylib は `hako-raylib-hello` のサブモジュールを共有して静的に組み込む。標準フォントに日本語が無いので、画面の文字は英語。

### LÖVE サンプル (`samples/love-hello`)

リンク: [LÖVE](https://love2d.org/) / [Wiki](https://love2d.org/wiki/Main_Page) / [GitHub](https://github.com/love2d/love)

- LÖVE 本体は `hako-love` (12.0 開発版、SDL3)。ゲームは `love <フォルダか .love>` で動く。

```bash
rsync -a samples/love-hello/ root@192.168.7.2:/data/dev/apps/love-hello/
scp samples/love-hello/love-hello.app root@192.168.7.2:/data/dev/apps/
ssh root@192.168.7.2 /usr/lib/hako/launch-app love-hello
```

- Lua からは刻印を取れないので、`joystick:getGamepadType()` と `HAKO_PAD_LAYOUT` を見て読み替える (main.lua 参照)。
- 描画は Vulkan が選ばれる。`LOVE_GRAPHICS_USE_OPENGLES=1` で GLES に変えられる。

### Siv3D

リンク: **出発点 [wtnbgo/siv3d_app](https://github.com/wtnbgo/siv3d_app)** (SDL3 版 Siv3D のアプリのひな形。`siv3d-app.json` に `rpmini` ターゲットがある) /
SDL3 版 [wtnbgo/OpenSiv3D `develop_sdl3`](https://github.com/wtnbgo/OpenSiv3D/tree/develop_sdl3) /
arm64 のビルド用コンテナ [wamsoft/steamdev `deckbuild/`](https://github.com/wamsoft/steamdev/tree/master/deckbuild) /
[Siv3D](https://siv3d.github.io/) / [OpenSiv3D (本家)](https://github.com/Siv3D/OpenSiv3D)

- SDL3 版の OpenSiv3D を arm64 Linux 向けにビルドし、アプリ一式を `/data/dev/<exeName>/` に転送、
  `/data/dev/apps/<exeName>.app` で登録して `launch-app` で起動する。
- アセットを作業ディレクトリからの相対パスで読むので、`.app` の `Dir=` はアプリのフォルダにする。
- 全画面は環境変数 `SIV3D_FULLSCREEN=1` (セッションの既定で有効)。
- siv3d_app を元にアプリを作り、`python3 <OpenSiv3D>/tools/siv3d_app.py --project <アプリ> --target rpmini all` でビルド、
  `... --target rpmini run` で転送・`.app` の登録・`launch-app` での起動までをまとめて行う
  (ビルドは steamdev の `deckbuild/` の rpmini 用コンテナ。接続先は `siv3d-app.json` の `rpmini.device`)。

#### Siv3D ゲーム集 (`hako-siv3d-games`)

[Siv3D のサンプル「ゲーム」](https://siv3d.github.io/ja-jp/samples/games/) の 22 本を、1 つのアプリにまとめたもの。
メニューから選び、パッドとタッチで遊べる。Siv3D で作るときの見本にもなる。

- 構成 (`packages/hako-siv3d-games/src/`):
  - `Input.hpp`: パッド・キーボード・マウス・タッチを「決定 / 戻る / 方向 / ポインター」にまとめる。
    A / B は刻印どおり (Switch 配置かどうかは SDL から判定)。マウスで遊ぶゲームでは、スティックでポインターを動かし A でクリックする。
  - `Games.cpp`: ゲームの一覧 (番号・名前・操作説明・画面の大きさ)。`games/Gnn_*.cpp` が各ゲーム。
  - 画面はサンプルが想定した大きさ (800x600 など) のまま、`ResizeMode::Keep` で拡大して余白を付ける。
  - START+SELECT / HOME / Esc でメニューに戻る。ライセンスはメニューの「ライセンス」で読める (`assets/licenses/`)。
- 元のコードと変更点は、各ファイルの先頭に書いてある。主な変更:
  - 15 パズル: ファイル選択の代わりに絵文字から絵柄を作る。タイピング: 画面のキーボード。音ゲー: 譜面を組み込み。
  - スロット: 外部フォントの代わりに同梱の Heavy。2D RPG: 第三者のマップチップ素材は同梱できないので、図形と絵文字で描く (マップの配置はサンプルのまま)。
- ライセンス: 1〜12・21・22 は Siv3D のドキュメントのサンプル (MIT。著作権表示と全文を `assets/licenses/siv3d-docs.txt` に入れた)、
  13〜20 は [Siv3D-Samples](https://github.com/Siv3D/Siv3D-Samples) と [Reputeless/games](https://github.com/Reputeless/games) (CC0)。
  hako のための変更は MIT。
- ビルド: `scripts/build-packages.sh hako-siv3d-games` (中で `siv3d_app.py --target rpmini stage` を呼ぶので、docker と deckbuild-rpmini のイメージが要る)。
  OpenSiv3D は `siv3d-app.json` の `siv3d.ref` で commit を固定している。手元の作業コピーを使うときは `SIV3D_BASE=<OpenSiv3D>` を付ける。
- 開発中は `SIV3D_BASE=<OpenSiv3D> python3 <OpenSiv3D>/tools/siv3d_app.py --project packages/hako-siv3d-games --target rpmini run` で転送・起動できる。

### 吉里吉里Z

リンク: **出発点 [wamsoft/krkrz_dev](https://github.com/wamsoft/krkrz_dev)** (ワムソフト版の本体とプラグインの統合リポジトリ。SDL3 版のビルドとドキュメント) /
[wamsoft/krkrz_linux](https://github.com/wamsoft/krkrz_linux) (Linux 向け配布物の外枠。x86_64 の Steam Linux Runtime 向けと、`ARCH=arm64` で hako 向け) /
arm64 のビルド用コンテナ [wamsoft/steamdev `deckbuild/`](https://github.com/wamsoft/steamdev/tree/master/deckbuild) /
本体 [wamsoft/krkrz](https://github.com/wamsoft/krkrz) / [吉里吉里Z (krkrz/krkrz)](https://github.com/krkrz/krkrz)

krkrz_linux を使うと、arm64 ビルドから実機への転送・`.app` の登録・起動までを make 一発で行える。
krkrz_dev と krkrz_linux を同じ親ディレクトリに clone しておく。

```sh
# 初回だけ: rpmini 用のビルドコンテナを作る (steamdev を clone した場所で)
bash <steamdev>/deckbuild/deckbuild.sh -T rpmini image

export KRKRZ_BASE=~/work/kirikiri       # krkrz_dev と krkrz_linux の親
make -C $KRKRZ_BASE/krkrz_linux all ARCH=arm64      # ビルド (初回は 30 分ほど)
make -C $KRKRZ_BASE/krkrz_linux deploy ARCH=arm64   # 実機へ転送して起動 (付属のコアデモ)

# 自分のタイトル
PROJECT_DIR=/path/to/title make -C $KRKRZ_BASE/krkrz_linux all deploy ARCH=arm64
```

- 転送先と起動引数は、タイトルの `linux-config.json` の `"device": {host, baseDir, title, args}`、
  または環境変数 `KRKRZ_LINUX_DEVICE` / `KRKRZ_LINUX_DEVICE_DIR` / `KRKRZ_LINUX_SSH_OPTS` で指定する
  (既定は `root@192.168.7.2`、`/data/dev/<title>/`)。起動しないで転送だけなら
  `python3 $KRKRZ_BASE/krkrz_linux/tools/krkrz_linux.py deploy --arch arm64 --no-run`。
- deploy は `/data/dev/apps/<title>.app` を書く。例: `Exec=/data/dev/krkrz-sample/krkrz-sample`、
  `Args=/data/dev/krkrz-sample/data -fullscreen=yes`。
- 表示確認は付属デモの自動巡回が速い: `Args` に `-demotest -demotestcap=/tmp/kzdemo` を足して起動すると、
  全シーンを順に開いて `/tmp/kzdemo/sceneNN.png` に保存し、終わると自分で終了する。

## エージェントへの頼み方 (例)

- 「raylib サンプルを元に、`packages/hako-mygame/` で新しいゲームのひな形を作って。実機に入れてスクリーンショットを見せて」
- 「LÖVE で 2D のアクションを作りたい。`samples/` に置いて転送・起動までして。ボタンの確認は私がやるので手順を教えて」
- 「この .app で起動するとすぐ落ちる。ログを見て原因を調べて」
- 「画面を撮って、文字が切れていないか見て」

人の操作が要る確認 (ボタン・音・タッチ) は、エージェントに「手順を示して、準備ができたと言うまで待つ」よう頼みます。
