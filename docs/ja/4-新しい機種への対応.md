# 4. 新しい機種への対応

[English](../en/4-new-boards.md)

同じ系統の機種 (OpenABL で起動できる Qualcomm 機の携帯ゲーム機) で hako を動かすための手順です。
機種に依存しない部分 (`hako-*`) はそのまま使い、機種固有の部分を `<機種>-bsp` パッケージとイメージ定義に分けて足します。

> 新しい機種での作業は、ブートローダーの書き換えを伴います。まず [1-実機の準備.md](1-実機の準備.md) を
> Retroid Pocket Mini 向けとして読み、何をしているかを理解してから進めてください。

## 前提の確認

| 確認すること | 見るところ |
|---|---|
| OpenABL がその機種 (SoC) に対応しているか | [OpenABL](https://github.com/OpenHandheldCollective/OpenABL) の対応一覧とリリース |
| Linux のカーネルと DTS があるか | ROCKNIX など、その機種を動かしている配布物。メインラインの対応状況 |
| ファームウェア (GPU・DSP・Wi-Fi) の入手先 | linux-firmware、配布物の同梱物 |

- **SoC が同じ (SM8250) 機種** (Retroid Pocket 5、Mini V2、Flip 2 など) は、カーネルをそのまま使え、DTS と bsp の違いだけで済む見込みが高い。
- **SoC が違う機種**は、カーネルのビルド (`kernel/`) から作り直しになる。

## 進め方

### 1. 動いている状態の記録を取る (基準データ)

その機種で Linux が動く配布物 (ROCKNIX など) を SD から起動し、ssh などで次を取って保存します。
hako で動かないものがあったとき、比べる元になります。

```sh
dmesg; lsmod; cat /proc/cmdline; uname -a
ls -R /lib/firmware; zcat /proc/config.gz
cat /proc/bus/input/devices; amixer contents; aplay -l
ls /sys/class/drm; cat /sys/class/drm/*/modes
```

あわせて、ESP の起動エントリ (`loader/entries/*.conf`) と使っている dtb の名前を控えます。

### 2. カーネル

- `kernel/SOURCE.pin` と `kernel/build.sh` が、どの上流・どのパッチ・どの設定で作るかを決めている ([kernel/README.md](../../kernel/README.md))。
- 同じ SoC なら、新しい機種の dtb がビルドされて `/usr/lib/linux-image-*/` に入るかを確かめるだけでよいことが多い。
- 違う SoC なら、`kernel/soc/<SOC>.conf` と `kernel/firmware-<SOC>.list`、必要なら `kernel/config/soc-<SOC>/` を足し、
  `SOC=<SOC> kernel/build.sh` でビルドする。パッケージ名に SoC が入る (`linux-image-<ver>-sm4450`)。
  SM4450 での実例は [5-実例-RG55G1.md](5-実例-RG55G1.md)。

### 3. 機種パッケージ `<機種>-bsp`

`packages/rpmini-bsp/` をコピーして名前を変え、中身を新しい機種に合わせます。

| 中身 | 直すこと |
|---|---|
| 依存関係 (`debian/control`) | カーネルのパッケージ名、必要なファームウェア |
| ESP の更新 (`/usr/sbin/rpmini-update-esp`、`/etc/default/rpmini-esp`) | dtb の名前、起動エントリのファイル名、カーネルの起動オプション |
| USB ガジェット (`usb-gadget` と service、`*-usb0.network`) | USB コントローラの名前 (`/sys/class/udc`)。アドレスは揃えておくと楽 |
| UCM (`/usr/share/alsa/ucm2/...`) と WirePlumber の設定 | 音声の経路。基準データの `amixer contents` と配布物の UCM を元にする |
| udev ルール | パッドをジョイスティックとして扱わせる、タッチ座標の回転行列 |
| セッションの既定値 (`/usr/lib/hako/session.d/10-<機種>.sh`) | `HAKO_ROTATE` (パネルが縦長なら)、`SDL_GAMECONTROLLERTYPE` / `SDL_GAMECONTROLLERCONFIG` (パッドの割り当て) |
| 音量の予備 (`/usr/lib/hako/hw/volume`) | PipeWire が無いときのミキサーの名前 |

- パッドの割り当ては、実機で `evtest` を見ながら決めます (セッションがパッドを掴んでいるので、先に `systemctl stop hako-session`)。
  a/b/x/y は位置 (下/右/左/上) で書きます。刻印の並びは `SDL_GAMECONTROLLERTYPE` で SDL に伝えます。
- 画面の回転は cage が行います。タッチは cage が回さないので、同じ角度の補正行列を udev ルールで libinput に渡します。

### 4. イメージ定義

- `elbe/rpmini-dev.xml` をコピーして `elbe/<機種>-dev.xml` を作り、カーネルと bsp のパッケージ名、ホスト名、
  ESP の中身のコメントを直す。
- `BOARD=<機種> bash scripts/build-image.sh dev` でビルドする (`elbe/<機種>-dev.xml` を使う)。
- 最初の起動は OpenABL のメニューで、その機種を選んで起動する。

### 5. Android 側のスクリプト

`tools/rpmini-android/` をコピーして `tools/<機種>-android/` を作り、機種名 (`ro.product.model`)・SoC
(`ro.board.platform`)・OpenABL の elf とハッシュを、その機種のものに変えます。機種と SoC の確認は外さないでください。

### 6. 動作の確認

[リファレンス.md](リファレンス.md) の「ハードウェアの状態」の表を、新しい機種について埋めます。

| 項目 | 確かめ方 |
|---|---|
| 画面・GPU | ランチャーが出る、`vulkaninfo --summary`、`kmscube` |
| パッド・タッチ | SDL3 サンプルで ABXY の図・スティック・タッチの円 (人が操作) |
| 音・音量ボタン | サンプルの音、音量ボタン (人が聞く) |
| USB ネットワーク | `ssh root@192.168.7.2` |
| Wi-Fi・Bluetooth | `iwctl`、`bluetoothctl` |
| 起動時間 | `systemd-analyze` |

調査・準備・EDL でのバックアップと書き込み・初回起動までを通した実例は [5-実例-RG55G1.md](5-実例-RG55G1.md) にあります。

## エージェントへの頼み方 (例)

- 「Retroid Pocket 5 に対応したい。前提の確認から始めて。OpenABL・カーネル・DTS の状況を調べて、作業の見積もりを出して」
- 「ROCKNIX で取った基準データを `baseline/` に置いた。rpmini と比べて、bsp で変えるべきところを一覧にして」
- 「`packages/rp5-bsp/` を rpmini-bsp から作って。変えたところと、実機で確かめることを分けて説明して」
- 「パッドの割り当てを決めたい。evtest の結果を見るので、押すボタンの順番を指示して」

ブートローダーの書き込みや、パーティションに触る作業は、エージェントに判断させず人が行ってください。
