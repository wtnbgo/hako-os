# 3. アプリをまとめる (.deb → 専用イメージ)

[English](../en/3-packaging-an-app.md)

[2-開発の基本とサンプル.md](2-開発の基本とサンプル.md) の転送で動いたアプリを、配れる形にする手順です。

1. アプリを .deb にする (パッケージにすれば apt で入れられ、イメージにも入れられる)
2. 起動のしかたを決める (ランチャーから選ぶ / 電源を入れたらそのアプリだけ動く)
3. そのアプリを入れたイメージを作る (SD に書けば動く 1 つのパック)

> 今のイメージは「開発用 (dev)」の作りだけです。読み取り専用の root、A/B 更新、自動ロールバックといった
> 製品向けの仕組みはまだありません ([リファレンス.md](リファレンス.md) の「この先」)。

## 1. アプリを .deb にする

`packages/<パッケージ名>/` を作り、`scripts/build-packages.sh <パッケージ名>` で arm64 向けにビルドします。
ひな形はサンプルをコピーするのが早いです。

| アプリの種類 | ひな形 | ポイント |
|---|---|---|
| C / C++ でソースからビルド | `packages/hako-sdl-hello/` (Makefile)、`packages/hako-raylib-hello/` (CMake + サブモジュール) | debhelper がそのままビルドする |
| LÖVE のゲーム | (下の例) | `Depends: hako-love`、ゲームのフォルダか `.love` を入れるだけ |
| ビルド済みの実行ファイル (Siv3D・吉里吉里Z など) | (下の例) | `Architecture: arm64`、ファイルを置くだけ。同梱ライブラリに注意 |

置き場所の決まり:

| もの | 場所 |
|---|---|
| 実行ファイル | `/usr/bin/<名前>` (1 つだけのとき)、または `/usr/lib/<パッケージ名>/` |
| データ | `/usr/share/<パッケージ名>/` (読み取り専用。セーブは `$HOME` = `/var/lib/hako` 以下に書く) |
| ランチャーへの登録 | `/usr/share/hako/apps/<id>.app` |

最小の `debian/` (ビルド済みファイルを入れる例):

```
debian/control
  Source: mygame
  Section: games
  Priority: optional
  Maintainer: you <you@example.com>
  Build-Depends: debhelper-compat (= 13)
  Standards-Version: 4.7.0
  Rules-Requires-Root: no

  Package: mygame
  Architecture: arm64
  Depends: ${shlibs:Depends}, ${misc:Depends}
  Description: My game for hako

debian/rules            (実行権を付ける)
  #!/usr/bin/make -f
  %:
  	dh $@

debian/mygame.install
  dist/*        usr/lib/mygame/
  mygame.app    usr/share/hako/apps/

debian/changelog        (先頭の版が .deb の版になる。変えたら上げる)
debian/source/format    → 3.0 (native)
```

- LÖVE のゲームは `Depends: hako-love` にして、`.app` を `Exec=/usr/bin/love`、`Args=/usr/share/mygame` にする。
- ビルド済みの実行ファイルが自前の `libSDL3.so` などを同梱している場合は、`.app` の `Env=LD_LIBRARY_PATH=...` か
  実行ファイルの RPATH で、そのライブラリを使わせる (Debian の SDL3 と版が違うことがある)。
- `dpkg-shlibdeps` の警告 (同梱ライブラリが見つからない) は、同梱のものを使うなら無視してよい。
- ビルドしたら `bash scripts/dev-update.sh <パッケージ名>` で実機に入れて確かめる。

## 2. 起動のしかたを決める

| 方式 | やり方 |
|---|---|
| ランチャーから選ぶ (標準) | `.app` を入れるだけ。ランチャーが一覧に出す |
| 電源を入れたらそのアプリだけ | アプリを `hako-app` の alternative に、ランチャー (優先度 50) より高い優先度で登録する |
| 一時的に差し替える | `/etc/default/hako-session` (dev なら `/data/dev/session.env`) に `HAKO_APP=` と `HAKO_APP_ARGS=` |

アプリだけを動かす場合の postinst / prerm の例 (`packages/hako-sdl-hello/debian/` に同じ形があり、そちらは優先度 10):

```sh
# debian/mygame.postinst
#!/bin/sh
set -e
if [ "$1" = configure ]; then
	update-alternatives --install /usr/bin/hako-app hako-app /usr/lib/mygame/mygame 100
fi
#DEBHELPER#

# debian/mygame.prerm
#!/bin/sh
set -e
if [ "$1" = remove ]; then
	update-alternatives --remove hako-app /usr/lib/mygame/mygame
fi
#DEBHELPER#
```

- アプリが終了すると `hako-session` が 1 秒後に起動し直す (60 秒に 10 回まで)。アプリ側に「終了」を置かない作りでもよい。
- 音量ボタン・HOME ボタン・画面の回転・パッドの割り当ては、セッションと機種パッケージが面倒を見るので、アプリ側の作業は要らない。

## 3. そのアプリを入れたイメージを作る

1. dev のイメージ定義をコピーする: `cp elbe/rpmini-dev.xml elbe/rpmini-mygame.xml`
2. 新しい XML を直す:
   - `<name>` と `<description>`
   - `<pkg-list>`: 自分のパッケージを足し、要らないものを消す
     (配布用なら `hako-dev`・サンプル類は外す。`hako-dev` を外すと ssh やシリアルのログインも入らない)
   - イメージのファイル名: `<gpthd>` の `<name>` と `<set_packer>` の `rpmini-dev.img` を `rpmini-mygame.img` に
   - `<hostname>` など必要なもの
   - `<finetuning>`: dev 用の行を合わせて直す (`/root/.ssh` の chmod、`iwd` の有効化などは hako-dev が前提)
3. ビルドする: `bash scripts/build-image.sh mygame` → `out/images/mygame/rpmini-mygame.img`
   (ssh の鍵を入れるのは `dev` のときだけ。`<archivedir>` の `build/elbe/overlay` は毎回作り直されるので、そのままでよい)
4. SD に書いて起動を確かめる。配るときは `xz -T0` で圧縮し、`sha256sum` を添える。

- `out/images/<種類>/licence-target.txt` に、イメージに入った Debian パッケージのライセンス一覧ができる。配布時に添える。
- イメージのビルド中 (KVM で 15〜20 分) は、`build-packages.sh` / `publish-repo.sh` / `dev-update.sh` を動かさない
  (ELBE がビルドの間ずっと `repo/` を読むため、途中でパッケージが消えると失敗する)。

## エージェントへの頼み方 (例)

- 「`/data/dev/mygame` で動いているアプリを `packages/mygame/` の .deb にして。ランチャーに出るようにして、実機に入れて確認して」
- 「mygame だけが起動するイメージの XML を作って。hako-dev とサンプルは外して、差分を見せて」
- 「イメージをビルドして。終わったら SD に書く手順と、最初の起動で確かめることを教えて」
