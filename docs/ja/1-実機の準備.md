# 1. 実機の準備

[English](../en/1-device-setup.md)

バックアップを取り、ブートローダー (ABL) を OpenABL に書き換え、dev イメージを microSD に書いて起動するまでの手順です。
対応している機種は次の 2 つです。

| 機種 | SoC | OpenABL のメニューで選ぶ機種 |
|---|---|---|
| Retroid Pocket Mini (V1) | SM8250 | Retroid Pocket Mini (V2 ではない) |
| Anbernic RG 55G1 | SM4450 | Anbernic RG 55G1 |

バックアップと書き込みは、PC から **EDL** (Qualcomm の 9008 モード) で行います。
EDL は ABL より前の段階で動くので、Android が無くても、ABL を書き損じても使えます。PC は Windows でも Linux でも構いません。

> **注意**: ブートローダーを書き換えます。メーカーの保証外の作業で、失敗すると Android も起動しなくなることがあります。
> 自己責任で、手順を理解してから進めてください。スクリプトは機種ごとのローダーと OpenABL のハッシュを確かめ、
> 違えば何も書きません。上の表に無い機種では使わないでください ([4-新しい機種への対応.md](4-新しい機種への対応.md))。

## 全体の流れ

1. PC に EDL のツールを入れる (Windows は QPST、Linux は qdl)
2. 本体を EDL に入れ、個体固有のパーティションをバックアップする (読むだけ)
3. 本体を EDL に入れ、ABL を OpenABL に書き換える (書く前に照合、書いた後に読み戻して照合)
4. PC で dev イメージを作り (または入手し)、microSD に書く
5. SD を挿して起動し、PC と USB でつないで ssh で入る

内蔵の Android は消しません。起動時に **音量 +** を押していれば Android が起動します。

## 用意するもの

- 対応機種の本体
- microSD カード (8GB 以上。dev イメージは 7GiB で、初回起動時にカードいっぱいまで広がる)
- USB-C ケーブル (PC と**直結**する。ハブ経由だと EDL や USB のデバイスモードが不安定になることがある)
- PC: Windows 10/11 か Linux (Debian trixie、Ubuntu 26.04 で確認)。イメージを自分で作るなら Debian trixie (WSL2 でも可)
- このリポジトリ (`tools/edl/hako_edl.py`。Python 3 の標準ライブラリだけで動く)
- 機種ごとのファイル (リポジトリには入れていない。入手してハッシュを確かめる):

| | Retroid Pocket Mini | Anbernic RG 55G1 |
|---|---|---|
| EDL のローダー | `prog_firehose_ddr.elf`: Retroid の純正ファームウェアの復旧用一式 (QFIL 用、Android 13 版 `RPMini_A13_20250121`) に入っているもの | `xbl_s_devprg_ns.melf`: TheGammaSqueeze/sd-tools の `stock/firmware/` にあるもの |
| その sha256 | `690bd3920e637d66584314929f1198818b8163a1f84a4d3200c60922defb9d16` | `4268562be8c612b3036fde519a64edac3afd65b8b31c483dcd345b24cc5ee19c` |
| OpenABL v1.2 の elf | `abl_signed-SM8250.elf` | `abl_signed-SM4450.elf` |
| その sha256 | `628dbff74f5b570b897c14725f2c36ff2ca5fe018998e2c248a3d15d906ccef9` | `8d73232614bdf50d602dfb934157328b95fc90f1ea22ba71dbc8836bc7aa8a3b` |

OpenABL の elf は [OpenABL](https://github.com/OpenHandheldCollective/OpenABL) のリリースから取ります。
ローダーは本体の中で動いて読み書きを行うプログラムで、機種 (SoC) ごとに違います。

## 1. PC に EDL のツールを入れる

### Windows

| もの | 入れ方 |
|---|---|
| Python 3 | `winget install Python.Python.3.13` (または python.org から)。`py -3` で動けばよい |
| QPST 2.7 | `QSaharaServer.exe` と `fh_loader.exe` を使う。Retroid の復旧用一式に入っている `qpst.win.2.7_installer_00495.1.zip` (中の `QPST.2.7.496.1.exe`) を管理者で入れる。`C:\Program Files (x86)\Qualcomm\QPST\bin` に入る |
| Qualcomm USB ドライバ | 同じく一式に入っている `Qualcomm_USB_Driver_v1.0.10061.1.zip` (または `qualcomm_hsusb_drv_*.exe`) を管理者で入れる |

EDL に入れると、デバイスマネージャーの「ポート (COM と LPT)」に **Qualcomm HS-USB QDLoader 9008 (COMn)** が出ます。
スクリプトはこのポートを自動で見つけます (`--port COMn` で指定もできる)。

### Linux

- **Ubuntu 26.04**: `sudo apt install qdl` (2.4 で確認)。
- **Debian trixie**: trixie 本体の qdl は古いので、backports の 2.8 を入れる。

  ```bash
  printf 'Types: deb\nURIs: http://deb.debian.org/debian\nSuites: trixie-backports\nComponents: main\nSigned-By: /usr/share/keyrings/debian-archive-keyring.gpg\n' | sudo tee /etc/apt/sources.list.d/backports.sources
  sudo apt update && sudo apt install -t trixie-backports qdl
  ```

- sudo なしで使うために、udev の規則を入れる (plugdev グループの人が EDL の本体を開けるようになる):

  ```bash
  sudo cp tools/edl/51-qcom-edl.rules /etc/udev/rules.d/ && sudo udevadm control --reload
  ```

- WSL2 からは試していません (USB を渡すには usbipd が要る)。素の Linux を使ってください。
- qdl は 1 回の実行が終わると本体を再起動します。そのため Linux では、確認と書き込みのたびに EDL に入り直します (スクリプトが待って案内する)。

## 2. EDL に入る

| 機種 | 入り方 |
|---|---|
| Retroid Pocket Mini | 電源を切り、USB ケーブルを抜く。**音量 + と音量 - を両方押したまま** ケーブルを挿し、2〜3 秒たったら離す。電源ボタンとの組み合わせでは入らない |
| Anbernic RG 55G1 | Android で USB デバッグを有効にして `adb reboot edl` |

- 画面は黒いままです。PC に 9008 の機器が現れれば入っています (Windows はデバイスマネージャー、Linux は `lsusb -d 05c6:9008`)。
- EDL から抜けるには、電源ボタンを 10〜15 秒長押しします (スクリプトは終わるときに自分で再起動させる)。
- 入ったまましばらく置いた本体は応答しないことがあります (`failed to read sahara request` など)。そのときは抜けて入り直します。

## 3. バックアップ

保存先のフォルダ (`<dir>`) を作り、ローダーをそこに置きます。機種の指定は `rpmini` か `rg55g1` です。

```bash
mkdir -p ~/hako-backup && cp prog_firehose_ddr.elf ~/hako-backup/     # RG 55G1 は xbl_s_devprg_ns.melf
python3 tools/edl/hako_edl.py rpmini backup ~/hako-backup               # Windows では py -3 tools\edl\hako_edl.py ...
```

1. スクリプトが「waiting for the device in EDL」と出したら、本体を EDL に入れる。
2. GPT (各 LUN の先頭 6 セクター) と、機種ごとに決めたパーティション (ABL、persist、modemst、devinfo など 26〜29 個) を読み、
   `SHA256SUMS` と `parts.txt` (パーティションの一覧) を作る。最後が `RESULT=BACKUP_OK` になること。
3. **`<dir>` を丸ごと PC の別の場所にも写して保管する。** 個体ごとに違う値 (校正データなど) を含み、ほかの個体からは戻せません。

- OpenABL を書く**前**に取ってください。書いた後のバックアップには純正の ABL が入りません (スクリプトが注意を出す)。
- 起動するたびに書き換わるパーティション (logfs、persist、uefivarstore など) は、取るたびに少し違います。

## 4. OpenABL を書く (人が了承してから)

OpenABL の elf を置き、まず確認だけ行います。

```bash
python3 tools/edl/hako_edl.py rpmini check ~/hako-backup abl_signed-SM8250.elf
```

- 書き込みはしません。ローダーと elf のハッシュ、バックアップの `SHA256SUMS` を確かめ、今の abl_a / abl_b を読んで
  `stock` (バックアップと同じ純正) か `OpenABL` かを表示します。最後が `RESULT=CHECK_OK` になること。
- 終わると本体は再起動します。次の `flash` の前に、もう一度 EDL に入れてください。

問題なければ書きます。

```bash
python3 tools/edl/hako_edl.py rpmini flash ~/hako-backup abl_signed-SM8250.elf
```

- 今の ABL をもう一度確かめ (純正か OpenABL でなければ止まる)、`yes` と入力すると abl_a と abl_b に書き、読み戻して照合します。
  `RESULT=SUCCESS` を確認してください。
- Windows は 1 回の EDL で、この確認から書き込みまで続けて行います。Linux は確認のあとで本体が再起動するので、もう一度 EDL に入れます。
- 書き込むのは elf の長さ (520 KiB) だけです。パーティションの残りには前の中身が残りますが、起動には影響しません。
- `RESULT=VERIFY_FAILED` が出たら、そのままにせず `restore` で純正に戻してください (EDL は ABL に関係なく使える)。

## 5. イメージを用意して SD に書く

```bash
git clone --recursive https://github.com/wtnbgo/hako-os && cd hako-os
kernel/build.sh                        # カーネルの .deb (初回だけ。RG 55G1 は SOC=SM4450 kernel/build.sh)
bash scripts/build-image.sh dev        # → out/images/dev/rpmini-dev.img (RG 55G1 は BOARD=rg55g1 を付ける)
```

- 初回はビルド環境の準備が要ります (ELBE の initvm 作成に 30 分前後)。[リファレンス.md](リファレンス.md) の「ビルド環境」を参照。
- dev イメージには、ビルドした PC の ssh 公開鍵 (`~/.ssh/id_*.pub`) が root 用に入ります。
- 書き込みは balenaEtcher や `dd` で。SD の中身はすべて消えます。

## 6. 起動して接続する

1. 電源を切り、SD を挿して起動する。初回は **音量 -** を押しながら起動して OpenABL のメニューを出し、
   - Device model → 冒頭の表の機種 (違うものを選ぶと画面が出ない。SD が無いと `no device trees found` と出る)
   - Boot mode → Linux、Boot source → Auto (または SD card)
   - Start
2. 数秒でランチャーが出る。初回起動では `/data` が SD の最後まで自動で広がる。
3. USB-C で PC に直結し、`ssh root@192.168.7.2`。PC 側には 192.168.7.x のアドレスが自動で付く。
   2 台とも同じアドレスなので、RG 55G1 には別名で入ります: `ssh -o HostKeyAlias=rg55g1 root@192.168.7.2`。

| 起動時の操作 | 結果 |
|---|---|
| 何も押さない | SD の起動エントリから Linux |
| 音量 - | OpenABL のメニュー |
| 音量 + | 内蔵の Android |

| 起動後の電源ボタン | 結果 |
|---|---|
| 短く押す | スリープ (もう一度押すと復帰) |
| 5 秒長押し | シャットダウン (ランチャーの設定からもできる) |

> スリープは気休め程度で、電池はあまり持ちません (SoC が深い省電力状態に入らないため。リファレンスの 4 章)。
> 電池を持たせたいときはシャットダウンしてください。しばらく操作しないと画面は自動で消えます (設定の「画面を消すまで」)。

## 元に戻す

- 一時的に Android: 起動時に音量 +。
- 完全に純正へ: EDL で `restore`。バックアップの abl_a / abl_b を書き戻して照合する。

  ```bash
  python3 tools/edl/hako_edl.py rpmini restore ~/hako-backup
  ```

- バックアップに純正の ABL が無い (OpenABL を書いた後に取った) ときは、純正の ABL のファイルを `--stock` で渡す。
  Retroid Pocket Mini では、復旧用一式 (Android 13 版) の `abl.elf` が純正の ABL と同じものでした (`cf5713…`)。
  `check` と `flash` も、同じ `--stock` で純正かどうかを判定できます。
- Android も起動しない: メーカーの復旧用一式を QFIL などで書き戻す。個体固有のパーティションはバックアップから戻す。

## 別の方法: Android の root スクリプト (Retroid Pocket Mini)

EDL を使えないときのために、Android 上で行うスクリプトも残しています (`tools/rpmini-android/`)。
本体の内部ストレージの `hako/` に中身と OpenABL の elf を置き、設定 → Handheld Settings → Advanced → Run Script as Root から
`run_backup.sh` → `run_check.sh` → `run_flash.sh` の順に実行します (`hako/flash.log` に `RESULT=` が出る)。

- このスクリプトで取ったバックアップは、LUN 4 と 5 の GPT が 0 で埋まっていました (Android から読めない)。EDL の方が確実です。
- RG 55G1 の純正ファームウェア (V3.0.9) では、この方法は使えませんでした ([5-実例-RG55G1.md](5-実例-RG55G1.md) の 1.2)。

## エージェントへの頼み方 (例)

- 「`docs/ja/1-実機の準備.md` の 5 を進めて。ビルド環境が無ければ、何を入れるか先に見せて」
- 「EDL のバックアップを取りたい。`hako_edl.py backup` を動かして、EDL に入れる合図をして」
- 「SD に書いて起動したので、ssh で入って hako-session・ランチャー・`/data` の大きさ・ネットワークを確認して」

ABL の書き込み (`flash` / `restore`) は、人が了承してから行ってください。エージェントに任せる場合も、
何を書くか (`check` の結果) を人が見て「書いてよい」と返してから実行させます。
