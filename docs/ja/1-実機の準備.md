# 1. 実機の準備 (Retroid Pocket Mini 専用)

[English](../en/1-device-setup.md)

> **注意: この手順は Retroid Pocket Mini (V1, SM8250) 専用です。** スクリプトは機種と SoC を確かめ、
> 違えば何もしません。ほかの機種で同じことをすると、起動しなくなるおそれがあります。
> 別の機種は [4-新しい機種への対応.md](4-新しい機種への対応.md) を見てください。
>
> ブートローダー (ABL) を書き換えます。メーカーの保証外の作業で、失敗すると Android も起動しなくなることがあります。
> 自己責任で、手順を理解してから進めてください。

## 全体の流れ

1. Android 上で、個体固有のパーティションをバックアップする (読むだけ)
2. Android 上で、ABL を OpenABL に書き換える (書く前に照合、書いた後に読み戻して照合)
3. PC で dev イメージを作り (または入手し)、microSD に書く
4. SD を挿して起動し、PC と USB でつないで ssh で入る

内蔵の Android は消しません。起動時に **音量 +** を押していれば Android が起動します。

## 用意するもの

- Retroid Pocket Mini (V1)。Android で root 権限のスクリプトを実行できること
  (設定 → Handheld Settings → Advanced → Run Script as Root)
- microSD カード (8GB 以上。dev イメージは 7GiB で、初回起動時にカードいっぱいまで広がる)
- PC: Debian trixie (WSL2 でも可)。イメージを自分で作るなら [リファレンス.md](リファレンス.md) の「ビルド環境」
- USB-C ケーブル (PC と**直結**する。ハブ経由だと USB のデバイスモードにならないことがある)
- OpenABL v1.2 の `abl_signed-SM8250.elf` ([OpenABL](https://github.com/OpenHandheldCollective/OpenABL) のリリースから。
  sha256 `628dbff74f5b570b897c14725f2c36ff2ca5fe018998e2c248a3d15d906ccef9`)

## 1. バックアップ

`tools/rpmini-android/` の中身と OpenABL の elf を、本体の内部ストレージの `hako/` フォルダにコピーします
(`/data/media/0/hako/`。PC から MTP や adb で)。

1. Run Script as Root で `hako/run_backup.sh` を実行する。
2. `hako/backup/` に `*.img`、GPT、`SHA256SUMS` ができる。`backup.log` で FAIL が無いことを見る。
3. **`hako/backup/` を丸ごと PC にコピーして保管する。** 個体ごとに違う値 (校正データなど) を含み、ほかの個体からは戻せません。

「Run Script as Root」は 1 行ずつ別コマンドとして送るので、実行するのは `run_*.sh` (1 行のラッパー) にします。
root が書いたファイルが PC から見えないときは、本体を再起動してつなぎ直します。

## 2. OpenABL を書く

1. `hako/run_check.sh` を実行する。書き込みはせず、機種・SoC・elf のハッシュ・現在の ABL がバックアップと一致するかを確かめる。
   `hako/flash.log` の最後が `RESULT=CHECK_OK` になること。
2. `hako/run_flash.sh` を実行する。abl_a → abl_b の順に書き、読み戻して照合する。`RESULT=SUCCESS` を確認する。
   - SUCCESS でなかったら、**再起動せずに** `hako/run_restore.sh` で純正 ABL に戻す。

## 3. イメージを用意して SD に書く

```bash
git clone --recursive https://github.com/wtnbgo/hako-os && cd hako-os
kernel/build.sh                        # カーネルの .deb (初回だけ。イメージに入る)
bash scripts/build-image.sh dev        # → out/images/dev/rpmini-dev.img (7GiB、KVM で 15〜20 分)
```

- 初回はビルド環境の準備が要ります (ELBE の initvm 作成に 30 分前後)。[リファレンス.md](リファレンス.md) の「ビルド環境」を参照。
- dev イメージには、ビルドした PC の ssh 公開鍵 (`~/.ssh/id_*.pub`) が root 用に入ります。
- 書き込みは balenaEtcher や `dd` で。SD の中身はすべて消えます。

## 4. 起動して接続する

1. 電源を切り、SD を挿して起動する。初回は **音量 -** を押しながら起動して OpenABL のメニューを出し、
   - Device model → **Retroid Pocket Mini** (V2 ではない。違うものを選ぶと画面が出ない)
   - Boot mode → Linux、Boot source → Auto (または SD card)
   - Start
2. 数秒でランチャーが出る。初回起動では `/data` が SD の最後まで自動で広がる。
3. USB-C で PC に直結し、`ssh root@192.168.7.2`。PC 側には 192.168.7.x のアドレスが自動で付く。

| 起動時の操作 | 結果 |
|---|---|
| 何も押さない | SD の起動エントリから Linux |
| 音量 - | OpenABL のメニュー |
| 音量 + | 内蔵の Android |

## 元に戻す

- 一時的に Android: 起動時に音量 +。
- 完全に純正へ: Android で `hako/run_restore.sh` (バックアップの abl_a/abl_b を書き戻して照合)。
- Android も起動しない: EDL モード (電源 + 音量 + + 音量 -) でメーカーの Android イメージを書き戻す。
  個体固有のパーティションはバックアップから戻す。

## エージェントへの頼み方 (例)

- 「`docs/ja/1-実機の準備.md` の 3 を進めて。ビルド環境が無ければ、何を入れるか先に見せて」
- 「SD に書いて起動したので、ssh で入って hako-session・ランチャー・`/data` の大きさ・ネットワークを確認して」
- 「OpenABL の書き込みログ (flash.log) を貼るので、問題が無いか見て」 (書き込みそのものは人が Android 上で行う)

エージェントにブートローダーの書き込みを直接させないでください。判断と実行は人が行い、エージェントには確認と説明を頼みます。
