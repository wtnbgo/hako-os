# 5. 実例: Anbernic RG 55G1 への対応

[English](../en/5-example-rg55g1.md)

[4-新しい機種への対応.md](4-新しい機種への対応.md) の手順を、実際の機種で進めた記録です。
SoC が違う機種 (Retroid Pocket Mini は SM8250、RG 55G1 は SM4450) なので、カーネルから作り分けています。
次の機種に対応するときの見本として、**何を調べ、何を根拠にどう決め、何を実機で確かめたか**を残します。

- 前半 (調査・準備) は、実機が届く前にリポジトリだけで済ませた作業です。
- 後半 (到着後) は、実機での確認手順と、その結果の記録欄です。作業しながら埋めていきます。

## 0. 全体の流れと所要時間

| 段階 | 内容 | 実機 | 目安 |
|---|---|---|---|
| 調査 | OpenABL・カーネル・DTS・ファームウェア・音声設定の入手先を確かめる | 不要 | 1〜2 時間 |
| カーネル | SoC ごとにビルドを分ける仕組みを入れ、SM4450 用をビルドする | 不要 | 実装 1 時間 + ビルド 8 分 |
| bsp | `rg55g1-bsp` を `rpmini-bsp` から作る | 不要 | 1 時間 |
| イメージ・Android | `elbe/rg55g1-dev.xml`、`tools/rg55g1-android/` | 不要 | 30 分 |
| バックアップ・OpenABL | Android でバックアップ → OpenABL を書く | 必要 | 30 分 |
| 初回起動・調整 | 画面の向き、タッチ、パッド、音、USB、Wi-Fi | 必要 | 半日〜 |

## 1. 調査

### 1.1 機種の素性

調べたのは主に ROCKNIX のソース (`projects/ROCKNIX/devices/SM4450/`) と、そこにある DTS です。
DTS は「この機種のハードウェアの一覧」として読めます。

| 項目 | 内容 | 根拠 |
|---|---|---|
| SoC | Qualcomm SM4450 (Snapdragon G1 Gen 2)、CPU は Cortex-A76 + A55、GPU は Adreno 613 | ROCKNIX の `options`、DTS の `compatible = "anbernic,rg55g1", "qcom,sm4450"` |
| 画面 | FocalTech FT7131M の縦長パネル (1080x1920)、DTS で `rotation = <90>` | DTS の panel ノード |
| タッチ | FocalTech FT5452 (I2C)。ドライバは `edt-ft5x06` | DTS、カーネル設定 `CONFIG_TOUCHSCREEN_EDT_FT5X06=y` |
| パッド | `singleadc-joypad` (ADC のスティック + GPIO のボタン)。ABXY は `BTN_SOUTH/EAST/WEST/NORTH`、十字キーは `ABS_HAT0X/Y`。ほかに `KEY_BACK` と `KEY_F10` のボタン | DTS の joypad ノード、ROCKNIX の inputplumber の割り当て (`KEY_F10` = Guide) |
| 音声 | q6 DSP (AudioReach) → スピーカーアンプ AW88166 ×2、ヘッドホンは WCD9370 (WCD937x) | DTS、UCM `Anbernic/RG55G1` |
| Wi-Fi / BT | WCN3990 (ath10k、SNOC 接続) / WCN3950 | DTS、ROCKNIX の `kernel-firmware.dat` |
| ストレージ | UFS (内蔵)、microSD | DTS |
| 映像出力 | なし (USB-C の DP Alt は使わない) | DTS に DP の出力がない |
| ファン | `pwm-fan`。DTS の温度設定 (thermal zone) とは結びついていない | DTS の `fan: pwm-fan` と `cooling-maps` |

> ファンは、カーネルが温度に応じて回すようにはなっていません (ROCKNIX はユーザー空間で制御している)。
> hako でどう扱うかは実機で音と温度を見て決めます (到着後の確認項目)。

### 1.2 ブートローダー (OpenABL)

- OpenABL v1.2 のリリースに SM4450 用の `abl_signed-SM4450.elf` が入っている。
  - sha256 `8d73232614bdf50d602dfb934157328b95fc90f1ea22ba71dbc8836bc7aa8a3b`、532480 バイト。
- 書き方は Retroid Pocket Mini と同じ (Android の root スクリプトで `abl_a` / `abl_b` に dd)。
- **違うのは、機種とプラットフォームの確認値**。
  - Android の `getprop ro.board.platform` と `ro.product.model` の値は、実機で読むまで分からない。
  - そのため、書き込みスクリプトは値が空のあいだ必ず止まるようにしてある。

### 1.3 カーネル

- ROCKNIX は SM4450 を同じカーネル 7.2 系・同じ commit で扱っている。
  - 機種のパッチは `devices/SM4450/patches/linux/`。当てる順番の規則は SM8250 と同じ (共通分と合わせて 64 本)。
  - 設定は `devices/SM4450/linux/linux.aarch64.conf`。
- SM8250 と SM4450 は CPU の構成 (`cortex-a76.cortex-a55`) が同じだが、パッチと設定が違う。
  - そのため、カーネルのパッケージは SoC ごとに分ける (`linux-image-7.2.0-rpmini` と `linux-image-7.2.0-sm4450`)。
- 機種に要るドライバが設定に入っているかを、ビルドした設定で確かめた。

| 設定 | 値 |
|---|---|
| `CONFIG_JOYSTICK_SINGLEADC_JOYPAD` | y |
| `CONFIG_DRM_PANEL_FOCALTECH_FT7131M` | y |
| `CONFIG_SND_SOC_AW88166` | y |
| `CONFIG_SND_SOC_WCD937X` | m |
| `CONFIG_ATH10K_SNOC` | m |
| `CONFIG_SENSORS_PWM_FAN` | m |
| `CONFIG_BATTERY_QCOM_BATTMGR` | m |

### 1.4 ファームウェア

カーネルに埋め込むファームウェアは、出どころが 2 つに分かれる。

| 出どころ | ファイル |
|---|---|
| linux-firmware (SM8250 と同じタグ) | `qcom/a630_sqe.fw`、`ath10k/WCN3990/hw1.0/` の board-2.bin・firmware-5.bin・wlanmdsp.mbn |
| ROCKNIX の extra-firmware リポジトリ (commit を固定) | GPU の zap (`a613_zap.mbn`)、BT (`qca/cmbtfw13.tlv`、`cmnv13*.bin`)、DSP (`qcom/sm4450/RG55G1/adsp.mbn`)、Wi-Fi のコントローラ (`wpss.mbn`)、アンプの調整値 (`aw88166_acf.bin`)、音声のトポロジ (`qcom/sm8450/AnbernicRG55G1-tplg.bin`) |

- 機種固有の DSP などは linux-firmware に無く、ROCKNIX も extra-firmware から取っている。
- そこで `firmware-SM4450.list` では `extra:` 付きの行で区別し、取得元の commit を `kernel/soc/SM4450.conf` に固定した。
- ハッシュは初回のビルドで `firmware-SM4450.sha256` に記録され、以後はそれと照合される。

### 1.5 音声

- ROCKNIX の UCM (`Anbernic/RG55G1/` と `conf.d/sm8450/AnbernicRG55G1.conf`) をそのまま使う。
  - カードの名前は DTS の `model = "AnbernicRG55G1"` と一致する。
- 音量ボタンの予備 (PipeWire が無いとき) は、UCM に出てくるミキサー名で書いた。
  - スピーカーは `Left/Right PCM Playback Volume` (0〜511)、ヘッドホンは `HPHL/HPHR Volume` (0〜20)。
  - 実機の `amixer contents` で確かめる。
- WirePlumber の設定は Retroid Pocket Mini のもの (S16LE に固定) を出発点にした。
  - 同じ q6 DSP なので、同じ症状 (S24_LE で音が小さい) が出るかを実機で確かめる。

### 1.6 調べ方のこつ

- **DTS を最初に読む**。`compatible` を拾えば、要るドライバ・ファームウェア・設定がほぼ分かる。
- **配布物の「機種フォルダ」を丸ごと見る**。ROCKNIX なら `devices/<SoC>/` に、カーネルのパッチ・設定・
  ファームウェアの一覧・UCM・パッドの割り当て (inputplumber) が揃っている。
- **似た機種と比べる**。同じ SoC の別機種 (ここでは Retroid Pocket Classic) の DTS と比べると、
  どこが機種固有かが分かる。
- 分からない値は推測で埋めて **「TO CHECK」と書いておく**。実機での確認項目がそのまま grep で一覧になる。

## 2. 準備 (実機なしでできること)

### 2.1 カーネルを SoC ごとに分ける

`kernel/build.sh` は `SOC=` で対象を選ぶ。SoC ごとの違いは `kernel/soc/<SOC>.conf` にまとめた。

```sh
kernel/build.sh                 # SM8250 (Retroid Pocket Mini): linux-image-<ver>-rpmini
SOC=SM4450 kernel/build.sh      # SM4450 (Anbernic RG 55G1):    linux-image-<ver>-sm4450
```

| ファイル | 役割 |
|---|---|
| `kernel/soc/SM8250.conf`、`SM4450.conf` | ROCKNIX の機種フォルダ、パッケージ名の後ろ (`LOCALVER`)、パッケージの版 (`KERNEL_PKGREV`)、ファームウェアの一覧、作業フォルダ |
| `kernel/firmware-<SOC>.list` / `.sha256` | 埋め込むファームウェアとそのハッシュ |
| `kernel/config/soc-<SOC>/*.config` | SoC ごとの追加設定 (ホスト名の既定値、デバッグ情報を切る など) |
| `kernel/SOURCE.pin` | 共通 (カーネルの版、ROCKNIX の commit、linux-firmware のタグ) |

ここで決めたこと:

- **パッケージ名を SoC で分ける**ので、両方を同じ apt リポジトリに置ける。
  - `linux-libc-dev` だけは SoC によらず同じ中身なので、SM8250 のものだけをリポジトリに入れる。
- **ROCKNIX は SM4450 をデバッグ情報付きでビルドしている**。
  - そのままだと 68MB の `-dbg` パッケージが出来、ビルドも遅い。
  - hako では `config/soc-SM4450/20-no-debug-info.config` で切った。
- 作業フォルダは SoC ごと (`build/kernel-sm4450/`) に分け、カーネルの tar ball だけ共有する。

### 2.2 bsp パッケージ `rg55g1-bsp`

`packages/rpmini-bsp/` を元に作り、次のように変えた。

| ファイル | 中身 | 状態 |
|---|---|---|
| `etc/default/rg55g1-esp` | 起動エントリ名 `rg55g1`、dtb `qcom/sm4450-anbernic-rg55g1.dtb`、起動オプション | 確定 |
| `usr/sbin/rg55g1-update-esp` | ESP へカーネル・initrd・dtb を置く (`*-sm4450` のカーネルを探す) | 確定 |
| `usr/lib/rg55g1/usb-gadget` ほか | USB ネットワーク・シリアル。UDC は `/sys/class/udc` の最初のものを使う | TO CHECK (UDC が出るか) |
| `usr/share/alsa/ucm2/...` | ROCKNIX の UCM をそのまま | TO CHECK (鳴るか) |
| `usr/share/wireplumber/.../51-rg55g1.conf` | S16LE 固定、初期音量 | TO CHECK |
| `usr/lib/hako/hw/volume` | PipeWire 無しの音量ボタン | TO CHECK (ミキサー名) |
| `usr/lib/hako/session.d/10-rg55g1.sh` | `HAKO_ROTATE=270` | TO CHECK (向き) |
| `usr/lib/udev/rules.d/72-rg55g1-touch-rotate.rules` | タッチの回転行列 (270 度用) | TO CHECK |

Retroid Pocket Mini から **持ってこなかったもの**と理由:

| rpmini-bsp のファイル | 理由 |
|---|---|
| `70-rpmini-gamepad.rules` | Retroid のパッドはボタンを持たずマウスと誤認されるための補正。RG 55G1 のパッドは普通のボタンを出すので不要 (見込み) |
| `71-rpmini-wcd938x-nosleep.rules` | WCD938x 用。RG 55G1 は WCD937x なので、ヘッドホンの検出が止まる症状が出たら同様のものを足す |
| `display-audio-prime`、`HDMI-RP.conf` など | 映像出力 (DP) の音声用。RG 55G1 には映像出力がない |

### 2.3 イメージ定義

`elbe/rg55g1-dev.xml` を `elbe/rpmini-dev.xml` から作り、
名前・ホスト名 (`rg55g1`)・カーネルと bsp のパッケージ名・有効にするサービス名を変えた。

```sh
SOC=SM4450 kernel/build.sh
bash scripts/build-packages.sh                 # rg55g1-bsp を含めてリポジトリへ
BOARD=rg55g1 bash scripts/build-image.sh dev   # -> rg55g1-dev.img
```

### 2.4 Android 側のスクリプト

`tools/rg55g1-android/` を `tools/rpmini-android/` から作った。

- `rg55g1_backup.sh`: 保存するパーティションに `dtbo_a` と `vendor_boot_a` を足した (純正の DTS を後から見るため。書き戻しには使わない)。
- `openabl_flash.sh`: SM4450 の elf とハッシュに変更。`PLAT_EXPECT` / `MODEL_EXPECT` が空のあいだは書き込まずに止まる。
- `openabl_restore.sh`: 同じく `PLAT_EXPECT` が空なら止まる。

## 3. 到着後の手順

> ボタン・音・画面を見る確認は、エージェントが手順を伝え、人が「準備できた」と返してから進めます。

### 3.1 Android で記録とバックアップ

1. 開発者向けオプションで USB デバッグを有効にし、PC とつなぐ。
2. `tools/rg55g1-android/` を本体の内部ストレージにコピーし、Anbernic の設定にある「root でスクリプトを実行」で
   `run_check.sh` を走らせる。`flash.log` の `platform=... model=...` を控える。
3. `run_backup.sh` を走らせ、`hako/backup/` を丸ごと PC に保存する (この個体に戻す唯一の手段)。
4. 控えた値を `openabl_flash.sh` の `PLAT_EXPECT` / `MODEL_EXPECT` と `openabl_restore.sh` の `PLAT_EXPECT` に入れ、コミットする。

### 3.2 OpenABL を書く (人が行う)

5. `run_check.sh` で確認が全部通ることを見てから、`run_flash.sh` を走らせる。
6. 再起動して OpenABL のメニューが出ることを確かめる (音量ボタンで選ぶ)。

### 3.3 (任意) ROCKNIX で基準データを取る

7. 別の microSD に ROCKNIX の SM4450 版を書いて起動し、[4 章の「基準データ」](4-新しい機種への対応.md) のコマンドで記録を取る。
   hako で動かないものがあったときに比べる元になる。

### 3.4 hako の初回起動

8. `rg55g1-dev.img` を microSD に書き、OpenABL のメニューで起動する。
9. 画面にログが流れ、ランチャーまで来るかを見る。来ない場合は USB でつないで `ssh root@192.168.7.2`
   (出ない場合は Wi-Fi か、ROCKNIX で基準データを取ってから比べる)。

### 3.5 確認と調整の一覧

| 項目 | 確かめ方 | 直すところ |
|---|---|---|
| 画面の向き | ランチャーが横向きで正しく出るか | `HAKO_ROTATE` (`10-rg55g1.sh`) |
| タッチ | SDL3 サンプルで、触った位置に円が出るか | `72-rg55g1-touch-rotate.rules` |
| パッド | `evtest` で各ボタン。ABXY の位置と刻印 | `SDL_GAMECONTROLLERTYPE` (`10-rg55g1.sh`) |
| `KEY_BACK` / `KEY_F10` のボタン | `evtest`。ランチャーのメニューなどに割り当てるか | ランチャー |
| 音 (スピーカー・ヘッドホン) | サンプルの音、`aplay -l`、`amixer contents` | UCM、`51-rg55g1.conf` |
| 音量ボタン | 音量が変わるか (PipeWire あり / なし) | `hw/volume` |
| ヘッドホンの抜き差し | 切り替わるか。しばらく置いた後も検出されるか | WCD937x の nosleep ルール |
| USB ネットワーク・シリアル | `ssh root@192.168.7.2`、COM ポート | `usb-gadget` |
| Wi-Fi / Bluetooth | `iwctl`、`bluetoothctl`、ランチャーの BT 画面 | ファームウェア |
| ファン | 回っているか、音、温度 (`/sys/class/thermal`) | 制御方法を決める |
| 電池 | `/sys/class/power_supply` | - |
| GPU | `vulkaninfo --summary`、raylib / Siv3D サンプル | - |
| 起動時間 | `systemd-analyze` | - |

## 5. 次の機種への教訓

- **同じ配布物 (ROCKNIX) が同じ commit で扱っている機種なら、カーネルは「SoC の設定ファイルを 1 つ足す」で済む**。
  `kernel/soc/<SOC>.conf` と `firmware-<SOC>.list` を作り、`SOC=<SOC> kernel/build.sh`。
- 推測で埋めた値には必ず TO CHECK を付ける。`grep -rn "TO CHECK" packages/<機種>-bsp` が到着日の作業一覧になる。
- 書き込み系のスクリプトは、**確認値が空なら止まる**ようにしておく。値を入れ忘れたまま別の機種に書く事故を防ぐ。
- 元の機種の bsp を写すときは、各ファイルについて「なぜそれが要ったか」を確かめる。
  前の機種の不具合への対処 (パッドの誤認、コーデックの省電力) は、新しい機種では不要なことも、別の形で要ることもある。

- 「RG 55G1 が届いた。3.1 から進めたい。run_check.sh の結果を貼るので、PLAT_EXPECT と MODEL_EXPECT を埋めて」
- 「初回起動した。ssh でつながるので、3.5 の表の上から順に確かめたい。人が見る項目は手順を伝えてから始めて」
- 「確かめた結果を 4 章の記録に書き込んで、TO CHECK を消せたところはコメントも直して」
