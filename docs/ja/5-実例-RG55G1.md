# 5. 実例: Anbernic RG 55G1 への対応

[English](../en/5-example-rg55g1.md)

[4-新しい機種への対応.md](4-新しい機種への対応.md) の手順を、実際の機種で進めた記録です。
SoC が違う機種 (Retroid Pocket Mini は SM8250、RG 55G1 は SM4450) なので、カーネルから作り分けています。
次の機種に対応するときの見本として、**何を調べ、何を根拠にどう決め、何を実機で確かめたか**を残します。

- 前半 (調査・準備) は、実機が届く前にリポジトリだけで済ませた作業です。
- 後半 (到着後) は、実機での手順と、その結果の記録です。
  - 書き込みは予定していた Android の root スクリプトでも fastboot でもできず、**EDL** で行いました (3.2、3.3)。

## 0. 全体の流れと所要時間

| 段階 | 内容 | 実機 | 目安 |
|---|---|---|---|
| 調査 | OpenABL・カーネル・DTS・ファームウェア・音声設定の入手先を確かめる | 不要 | 1〜2 時間 |
| カーネル | SoC ごとにビルドを分ける仕組みを入れ、SM4450 用をビルドする | 不要 | 実装 1 時間 + ビルド 8 分 |
| bsp | `rg55g1-bsp` を `rpmini-bsp` から作る | 不要 | 1 時間 |
| イメージ・Android | `elbe/rg55g1-dev.xml`、`tools/rg55g1-android/` | 不要 | 30 分 |
| バックアップ・OpenABL | EDL でバックアップ → EDL で OpenABL を書く | 必要 | 1〜2 時間 (初回は調べながら半日) |
| 初回起動・調整 | 画面の向き、タッチ、パッド、音、USB、Wi-Fi、GPU、時計 | 必要 | 半日〜 |

## 1. 調査

### 1.1 機種の素性

調べたのは主に ROCKNIX のソース (`projects/ROCKNIX/devices/SM4450/`) と、そこにある DTS です。
DTS は「この機種のハードウェアの一覧」として読めます。

| 項目 | 内容 | 根拠 |
|---|---|---|
| SoC | Qualcomm SM4450 (Snapdragon G1 Gen 2)、CPU は Cortex-A76 + A55、GPU は Adreno 613 | ROCKNIX の `options`、DTS の `compatible = "anbernic,rg55g1", "qcom,sm4450"` |
| 画面 | FocalTech FT7131M の縦長パネル (1080x1920)、DTS で `rotation = <90>` | DTS の panel ノード |
| タッチ | FocalTech FT5452 (I2C)。ドライバは `edt-ft5x06` | DTS、カーネル設定 `CONFIG_TOUCHSCREEN_EDT_FT5X06=y` |
| パッド | `singleadc-joypad` (ADC のスティック + GPIO のボタン)。ABXY は `BTN_SOUTH/EAST/WEST/NORTH`、十字キーは `ABS_HAT0X/Y`。ほかに `KEY_BACK` と `KEY_F10` のボタン | DTS の joypad ノード、ROCKNIX の inputplumber の割り当て (`KEY_F10` = Guide) |
| 音声 | q6 DSP (AudioReach) → スピーカーアンプ AW88166 ×2、ヘッドホンは WCD9370 (WCD937x) | DTS、UCM `Anbernic/RG55G1` |
| Wi-Fi / BT | WCN3990 (ath10k、SNOC 接続) / WCN3950 | DTS、ROCKNIX の `kernel-firmware.dat` |
| ストレージ | UFS (内蔵)、microSD | DTS |
| 映像出力 | なし (USB-C の DP Alt は使わない) | DTS に DP の出力がない |
| ファン | `pwm-fan`。DTS の温度設定 (thermal zone) とは結びついていない | DTS の `fan: pwm-fan` と `cooling-maps` |

> ファンは、カーネルが温度に応じて回すようにはなっていません (ROCKNIX はユーザー空間で制御している)。
> hako でどう扱うかは実機で音と温度を見て決めます (到着後の確認項目)。

### 1.2 ブートローダー (OpenABL)

- OpenABL v1.2 のリリースに SM4450 用の `abl_signed-SM4450.elf` が入っている。
  - sha256 `8d73232614bdf50d602dfb934157328b95fc90f1ea22ba71dbc8836bc7aa8a3b`、532480 バイト。
- ROCKNIX の手順は、Android に更新版の Anbernic のアプリ (AnbernicControl.apk) を入れ、
  「Handheld Settings → Advanced → Root Scripts」から `dd` で `abl_a` / `abl_b` に書く、というもの。
- **到着した個体 (純正ファームウェア V3.0.9) では、この方法も fastboot も使えなかった**。
  - Root Scripts は root (uid 0) で動くが、SELinux の枠が `system_app` のままで、`/dev/block` のどのパーティションも読めない
    (更新版のアプリを入れて再起動しても同じ)。
  - ブートローダーは出荷時からアンロックされている (`ro.boot.flash.locked=0`、`verifiedbootstate=orange`)。
    しかし `fastboot flash` は `unknown command` で断られる (書き込みは転送まで通り、Writing で失敗)。`fastboot oem edl` も同じ。
  - `adb root` も使えない (製品版のビルド)。
- そこで **EDL (Qualcomm の 9008 モード)** でバックアップと書き込みを行った (3.2、3.3)。
  - `adb reboot edl` で入れる。EDL は ABL より前の段階で動くので、ABL を書き損じても EDL から戻せる。
- Android で読んだ値は 4.1 にまとめた。

### 1.3 カーネル

- ROCKNIX は SM4450 を同じカーネル 7.2 系・同じ commit で扱っている。
  - 機種のパッチは `devices/SM4450/patches/linux/`。当てる順番の規則は SM8250 と同じ (共通分と合わせて 64 本)。
  - 設定は `devices/SM4450/linux/linux.aarch64.conf`。
- SM8250 と SM4450 は CPU の構成 (`cortex-a76.cortex-a55`) が同じだが、パッチと設定が違う。
  - そのため、カーネルのパッケージは SoC ごとに分ける (`linux-image-7.2.0-rpmini` と `linux-image-7.2.0-sm4450`)。
- 機種に要るドライバが設定に入っているかを、ビルドした設定で確かめた。

| 設定 | 値 |
|---|---|
| `CONFIG_JOYSTICK_SINGLEADC_JOYPAD` | y |
| `CONFIG_DRM_PANEL_FOCALTECH_FT7131M` | y |
| `CONFIG_SND_SOC_AW88166` | y |
| `CONFIG_SND_SOC_WCD937X` | m |
| `CONFIG_ATH10K_SNOC` | m |
| `CONFIG_SENSORS_PWM_FAN` | m |
| `CONFIG_BATTERY_QCOM_BATTMGR` | m |

### 1.4 ファームウェア

カーネルに埋め込むファームウェアは、出どころが 2 つに分かれる。

| 出どころ | ファイル |
|---|---|
| linux-firmware (SM8250 と同じタグ) | `qcom/a630_sqe.fw`、`ath10k/WCN3990/hw1.0/` の board-2.bin・firmware-5.bin・wlanmdsp.mbn |
| ROCKNIX の extra-firmware リポジトリ (commit を固定) | GPU の zap (`a613_zap.mbn`)、BT (`qca/cmbtfw13.tlv`、`cmnv13*.bin`)、DSP (`qcom/sm4450/RG55G1/adsp.mbn`)、Wi-Fi のコントローラ (`wpss.mbn`)、アンプの調整値 (`aw88166_acf.bin`)、音声のトポロジ (`qcom/sm8450/AnbernicRG55G1-tplg.bin`) |

- 機種固有の DSP などは linux-firmware に無く、ROCKNIX も extra-firmware から取っている。
- そこで `firmware-SM4450.list` では `extra:` 付きの行で区別し、取得元の commit を `kernel/soc/SM4450.conf` に固定した。
- ハッシュは初回のビルドで `firmware-SM4450.sha256` に記録され、以後はそれと照合される。

### 1.5 音声

- ROCKNIX の UCM (`Anbernic/RG55G1/` と `conf.d/sm8450/AnbernicRG55G1.conf`) をそのまま使う。
  - カードの名前は DTS の `model = "AnbernicRG55G1"` と一致する。
- 音量ボタンの予備 (PipeWire が無いとき) は、UCM に出てくるミキサー名で書いた。
  - スピーカーは `Left/Right PCM Playback Volume` (0〜511)、ヘッドホンは `HPHL/HPHR Volume` (0〜20)。
  - 実機の `amixer contents` で確かめる。
- WirePlumber の設定は Retroid Pocket Mini のもの (S16LE に固定) を出発点にした。
  - 同じ q6 DSP なので、同じ症状 (S24_LE で音が小さい) が出るかを実機で確かめる。

### 1.6 調べ方のこつ

- **DTS を最初に読む**。`compatible` を拾えば、要るドライバ・ファームウェア・設定がほぼ分かる。
- **配布物の「機種フォルダ」を丸ごと見る**。ROCKNIX なら `devices/<SoC>/` に、カーネルのパッチ・設定・
  ファームウェアの一覧・UCM・パッドの割り当て (inputplumber) が揃っている。
- **似た機種と比べる**。同じ SoC の別機種 (ここでは Retroid Pocket Classic) の DTS と比べると、
  どこが機種固有かが分かる。
- 分からない値は推測で埋めて **「TO CHECK」と書いておく**。実機での確認項目がそのまま grep で一覧になる。

## 2. 準備 (実機なしでできること)

### 2.1 カーネルを SoC ごとに分ける

`kernel/build.sh` は `SOC=` で対象を選ぶ。SoC ごとの違いは `kernel/soc/<SOC>.conf` にまとめた。

```sh
kernel/build.sh                 # SM8250 (Retroid Pocket Mini): linux-image-<ver>-rpmini
SOC=SM4450 kernel/build.sh      # SM4450 (Anbernic RG 55G1):    linux-image-<ver>-sm4450
```

| ファイル | 役割 |
|---|---|
| `kernel/soc/SM8250.conf`、`SM4450.conf` | ROCKNIX の機種フォルダ、パッケージ名の後ろ (`LOCALVER`)、パッケージの版 (`KERNEL_PKGREV`)、ファームウェアの一覧、作業フォルダ |
| `kernel/firmware-<SOC>.list` / `.sha256` | 埋め込むファームウェアとそのハッシュ |
| `kernel/config/soc-<SOC>/*.config` | SoC ごとの追加設定 (ホスト名の既定値、デバッグ情報を切る など) |
| `kernel/SOURCE.pin` | 共通 (カーネルの版、ROCKNIX の commit、linux-firmware のタグ) |

ここで決めたこと:

- **パッケージ名を SoC で分ける**ので、両方を同じ apt リポジトリに置ける。
  - `linux-libc-dev` だけは SoC によらず同じ中身なので、SM8250 のものだけをリポジトリに入れる。
- **ROCKNIX は SM4450 をデバッグ情報付きでビルドしている**。
  - そのままだと 68MB の `-dbg` パッケージが出来、ビルドも遅い。
  - hako では `config/soc-SM4450/20-no-debug-info.config` で切った。
- 作業フォルダは SoC ごと (`build/kernel-sm4450/`) に分け、カーネルの tar ball だけ共有する。

### 2.2 bsp パッケージ `rg55g1-bsp`

`packages/rpmini-bsp/` を元に作り、次のように変えた。状態は実機で確かめた後のもの。

| ファイル | 中身 | 状態 |
|---|---|---|
| `etc/default/rg55g1-esp` | 起動エントリ名 `rg55g1`、dtb `qcom/sm4450-anbernic-rg55g1.dtb`、起動オプション | 確定 |
| `usr/sbin/rg55g1-update-esp` | ESP へカーネル・initrd・dtb を置く (`*-sm4450` のカーネルを探す) | 確定 |
| `usr/lib/rg55g1/usb-gadget` ほか | USB ネットワーク・シリアル。UDC は `/sys/class/udc` の最初のもの | 確定 (PC から NCM と COM ポートが見える) |
| `usr/share/alsa/ucm2/...` | ROCKNIX の UCM をそのまま | スピーカーは確定。ヘッドホンへの切り替えは未解決 (4.3) |
| `usr/share/wireplumber/.../51-rg55g1.conf` | S16LE 固定、初期音量 | 鳴るのは確認。S24_LE で小さくなるかは TO CHECK |
| `usr/lib/hako/hw/volume` | PipeWire 無しの音量ボタン | ミキサー名は実機にある。PipeWire 無しでの動作は未確認 |
| `usr/lib/hako/session.d/10-rg55g1.sh` | 向き (`HAKO_ROTATE=270`)、パッドの配置と割り当て、GPU (hako-mesa) | 確定 |
| `usr/lib/udev/rules.d/72-rg55g1-touch-rotate.rules` | タッチの回転行列 (270 度用) | 確定 |
| `usr/lib/udev/rules.d/71-rg55g1-wcd937x-nosleep.rules` | WCD937x を眠らせない (到着後に追加) | 入れたが、これだけではヘッドホンは直らない |

Retroid Pocket Mini から **持ってこなかったもの**と理由:

| rpmini-bsp のファイル | 理由 |
|---|---|
| `70-rpmini-gamepad.rules` | Retroid のパッドはボタンを持たずマウスと誤認されるための補正。RG 55G1 のパッドは普通のボタンを出すので不要 (実機で確認) |
| `71-rpmini-wcd938x-nosleep.rules` | WCD938x 用。実機でヘッドホンの検出が遅れたので、WCD937x 用を同じ形で足した (上の表) |
| `display-audio-prime`、`HDMI-RP.conf` など | 映像出力 (DP) の音声用。RG 55G1 には映像出力がない |

### 2.3 イメージ定義

`elbe/rg55g1-dev.xml` を `elbe/rpmini-dev.xml` から作り、
名前・ホスト名 (`rg55g1`)・カーネルと bsp のパッケージ名・有効にするサービス名を変えた。

```sh
SOC=SM4450 kernel/build.sh
bash scripts/build-packages.sh                 # rg55g1-bsp を含めてリポジトリへ
BOARD=rg55g1 bash scripts/build-image.sh dev   # -> rg55g1-dev.img
```

### 2.4 Android 側と EDL のスクリプト

- `tools/rg55g1-android/`: `tools/rpmini-android/` から作った、Android の root スクリプト用。
  - `rg55g1_backup.sh`: 保存するパーティションに `dtbo_a` と `vendor_boot_a` を足した (純正の DTS を後から見るため)。
  - `openabl_flash.sh` / `openabl_restore.sh`: 機種の確認値 (`PLAT_EXPECT` / `MODEL_EXPECT`) が空のあいだは止まる。値は到着後に入れた。
  - **V3.0.9 ではパーティションを読めないので、バックアップにも書き込みにも使えなかった** (1.2)。`run_check.sh` で機種の値を確かめるのには使える。
- `tools/rg55g1-edl/edl_xml.py`: EDL で使う fh_loader の XML を作る (到着後に追加)。
  - `gpt`: 各 LUN の GPT を読む XML。`backup`: 読んだ GPT から、指定したパーティションを読み出す XML と一覧 (`parts.txt`)。
    `flash`: ファイルを指定したパーティションに書く XML と、書いた範囲を読み直す XML。
  - パーティションの位置は毎回 GPT から求めるので、番号を手で書かない。

## 3. 到着後の手順

> ボタン・音・画面を見る確認は、エージェントが手順を伝え、人が「準備できた」と返してから進めます。

### 3.1 Android で準備

1. 初期設定を済ませ、システム更新があれば当てる (今回は V3.0.9 になった)。
2. 開発者向けオプションで USB デバッグを有効にし、PC で `adb devices` に出ることを確かめる。
   ほかの Android 機器もつながっているときは `adb -s <シリアル>` で RG 55G1 を指す。
3. 機種の値とブートローダーの状態を読む (結果は 4.1)。

```sh
adb shell getprop ro.board.platform      # parrot
adb shell getprop ro.product.model       # RG 55G1
adb shell getprop ro.boot.flash.locked   # 0 (アンロック済み)
```

### 3.2 EDL でバックアップを取る

用意するもの (Windows):

| もの | 内容 |
|---|---|
| QPST | `QSaharaServer.exe` (ローダーを送る) と `fh_loader.exe` (読み書き)。QFIL 2.0.3.5 に入っていたもので動いた |
| Qualcomm USB ドライバ | EDL の本体が `Qualcomm HS-USB QDLoader 9008 (COMn)` として見える |
| firehose ローダー `xbl_s_devprg_ns.melf` | 本体側で動く読み書きのプログラム。TheGammaSqueeze/sd-tools の `stock/firmware/` にあるもの (Qualcomm のテスト用の鍵で署名、1.7 MB) を使った。第三者の配布物なのでリポジトリには入れない |

手順 (`<dir>` は保存先、`COMn` は EDL のときに増えた COM ポート):

```powershell
adb reboot edl                                   # 画面は黒いまま。COM ポートが増えれば入っている
QSaharaServer.exe -p \\.\COMn -s 13:xbl_s_devprg_ns.melf
python3 tools/rg55g1-edl/edl_xml.py gpt <dir>
fh_loader.exe --port=\\.\COMn --memoryname=UFS --sendxml=read_gpt.xml --convertprogram2read --search_path=<dir> --mainoutputdir=<dir> --noprompt --zlpawarehost=1
python3 tools/rg55g1-edl/edl_xml.py backup <dir> abl_a,abl_b,persist,devinfo,misc,modemst1,modemst2,fsg,fsc,keystore,frp,uefivarstore,secdata,storsec,ssd,cdt,ddr,splash,logfs,limits,limits-cdsp,apdp,dip,spunvm,dtbo_a,vendor_boot_a
fh_loader.exe --port=\\.\COMn --memoryname=UFS --sendxml=read_parts.xml --convertprogram2read --search_path=<dir> --mainoutputdir=<dir> --noprompt --zlpawarehost=1
fh_loader.exe --port=\\.\COMn --reset --noprompt --zlpawarehost=1   # Android で起動し直す
```

- `--convertprogram2read` を付けると、XML の `<program>` (書き込み) が読み出しになる。バックアップでは必ず付ける。
- 読み出したら各ファイルの sha256 を記録し、PC の別の場所にも写しておく (この個体に戻す唯一の手段)。
- `abl_a` / `abl_b` は LUN 4 にある (4.1)。ROCKNIX のスクリプトの `dd` と同じものを、EDL で読んだことになる。

### 3.3 EDL で OpenABL を書く (人が了承してから)

```powershell
python3 tools/rg55g1-edl/edl_xml.py flash <dir> abl_signed-SM4450.elf abl_a,abl_b
adb reboot edl
QSaharaServer.exe -p \\.\COMn -s 13:xbl_s_devprg_ns.melf
fh_loader.exe --port=\\.\COMn --memoryname=UFS --sendxml=write_abl_signed-SM4450.xml --search_path=<dir> --mainoutputdir=<dir> --noprompt --zlpawarehost=1
fh_loader.exe --port=\\.\COMn --memoryname=UFS --sendxml=readback_abl_signed-SM4450.xml --convertprogram2read --search_path=<dir> --mainoutputdir=<dir> --noprompt --zlpawarehost=1
```

1. `readback_abl_a.bin` と `readback_abl_b.bin` の sha256 が OpenABL の値 (`8d7323…`) と一致することを確かめる。
2. 音量マイナスを押したまま `fh_loader.exe --port=\\.\COMn --reset ...` で再起動し、OpenABL のメニューが出ることを確かめる。
3. 純正に戻すときは、同じ要領でバックアップの `abl_a.img` / `abl_b.img` をそれぞれのパーティションに書く
   (`edl_xml.py flash <dir> abl_a.img abl_a`、`abl_b` も同様)。

> OpenABL の「Device model」は、挿した microSD にある dtb から選択肢を作る。カードが無いと `no device trees found` と出るが、異常ではない。

### 3.4 (任意) ROCKNIX で基準データを取る

別の microSD に ROCKNIX の SM4450 版を書いて起動し、[4 章の「基準データ」](4-新しい機種への対応.md) のコマンドで記録を取る。
hako で動かないものがあったときに比べる元になる (今回は取らずに進めた)。

### 3.5 hako の初回起動

1. `rg55g1-dev.img` を microSD に書き、OpenABL のメニューで Device model に **Anbernic RG 55G1** を選んで Start。
2. スプラッシュからランチャーまで来るかを見る。
3. USB でつなぎ、`ssh root@192.168.7.2`。
   - Retroid Pocket Mini と同じアドレスなので、ssh のホスト鍵がぶつかる。RG 55G1 には別名で入る:
     `ssh -o HostKeyAlias=rg55g1 root@192.168.7.2`、更新は `HAKO_SSH_OPTS='-o HostKeyAlias=rg55g1' scripts/dev-update.sh`。
4. ランチャーまで来ず、USB でも入れないとき:
   - 電源ボタンの長押しで終了処理が動くか見る (動けば Linux は生きている)。
   - microSD を Linux の PC に挿し、rootA を読み取り専用でマウントして、前回の起動のログを読む:
     `journalctl -D <mnt>/var/log/journal -b -1 -p warning`。
     WSL の `wsl --mount` は USB 接続の SD カードリーダーを扱えないので、別の Linux 機を使った。

### 3.6 確認と調整の一覧

| 項目 | 確かめ方 | 直すところ |
|---|---|---|
| 画面の向き | ランチャーが横向きで正しく出るか | `HAKO_ROTATE` (`10-rg55g1.sh`) |

### 4.3 つまずいたこと

1. **Root Scripts でパーティションに触れない**。root だが SELinux の `system_app` のまま。`/dev/block` は一覧も読み出しも拒否された。
   どのパスでも同じ (`by-name`、`bootdevice`、`platform/...`、`sde1`、ディスク全体)。→ EDL に切り替えた。
2. **`fastboot flash` が `unknown command`**。アンロック済みでも、Anbernic の ABL は書き込みコマンドを持たない。→ EDL で書いた。
3. **OpenABL の Device model が `no device trees found`**。microSD を挿していなかっただけ。
4. **起動後に黒い画面** (バックライトは点灯、ボタンには反応しない)。
   - ログ: cage が `Unable to create the wlroots renderer`、その前に Mesa が `unsupported GPU id 0x0 / chip id 0xd506010300`。
   - Debian trixie の Mesa 25.0 も、backports の 26.1 も Adreno 613 を知らない。Mesa 26.2 で GPU の一覧に 1 行足されて対応した
     (`freedreno_devices.py` の `GPUId(613)`)。ROCKNIX は Mesa 26.2.4 なので、そのまま動いている。
   - まずソフトウェア描画 (`WLR_RENDERER=pixman`、`SDL_RENDER_DRIVER=software`) でランチャーを出し、ほかの確認を進めた。
   - 次に **hako-mesa** を作った: Debian の Mesa 26.2.6 の元 tarball (版と sha256 を固定) から、freedreno と turnip だけを
     LLVM なしでクロスビルド (2 分ほど)。`/usr/lib/hako/mesa` に置き、Debian の Mesa は置き換えない。
     セッションだけが `/usr/lib/hako/mesa/env.sh` (LD_LIBRARY_PATH、glvnd の EGL vendor、Vulkan ICD) で使う。
     Debian の Mesa が 26.2 以上になったら外す。
   - ビルドの注意: meson はそのままだと足りない部品 (libarchive、libxml2) をネットから取ってくる。
     `--wrap-mode=nodownload` にして、Debian のパッケージを使う。
5. **パッドの X と Y が逆**。SDL の自動割り当ては、このパッドの左右の扱いと合わない。`evtest` で押した順を記録して、明示の割り当てを書いた。
6. **時計が 4 月**。PMIC の RTC (rtc-pm8xxx) は電源が切れても数え続けるが、Linux から時刻を書けない
   (Android は自分で差分を覚えている)。NTP も入っていなかった。
   → `hako-rtc-offset` (時刻と RTC の差を保存し、起動の早い段階で戻す) と `systemd-timesyncd` を hako-base に入れた。
   `dev-update.sh` は PC の時刻に合わせる (古い時刻のままだと apt が「未来の日付」として断る)。
7. **ヘッドホン (未解決)**。差し込みがライン出力として扱われ (`Impedance detect ramp error`)、`Headphone Jack` が `off` のまま。
   差し込みの検出も遅く、抜いたことは検出されない。WCD937x を眠らせないルールでは直らなかった。カーネルの MBHC (DTS のしきい値など) を調べる必要がある。
8. **最初の起動で PC から USB が見えなかった**。2 回目以降は見えている。原因は分かっていない。

## 5. 次の機種への教訓

- **同じ配布物 (ROCKNIX) が同じ commit で扱っている機種なら、カーネルは「SoC の設定ファイルを 1 つ足す」で済む**。
  `kernel/soc/<SOC>.conf` と `firmware-<SOC>.list` を作り、`SOC=<SOC> kernel/build.sh`。
- **書き込みの手段を複数用意しておく**。Android の root、fastboot、EDL のどれが使えるかは、純正ファームウェアの版で変わる。
  EDL は ABL より前に動くので、ABL を書き損じても戻せる。バックアップも EDL で取れる。
- **GPU は Mesa の版で決まる**。新しい SoC は Debian 安定版の Mesa が知らないことがある。
  ソフトウェア描画でほかの確認を先に進め、Mesa は別に用意する (hako-mesa)。
- **RTC が書けない機種がある**。時計は NTP と保存した差分で保つ。
- 推測で埋めた値には必ず TO CHECK を付ける。`grep -rn "TO CHECK" packages/<機種>-bsp` が到着日の作業一覧になる。
- 書き込み系のスクリプトは、**確認値が空なら止まる**ようにしておく。値を入れ忘れたまま別の機種に書く事故を防ぐ。
- 元の機種の bsp を写すときは、各ファイルについて「なぜそれが要ったか」を確かめる。
  前の機種の不具合への対処 (パッドの誤認、コーデックの省電力) は、新しい機種では不要なことも、別の形で要ることもある。
- 入力の確認はアプリを止めてから。ボタンの記録中にランチャーがアプリを起動してしまう。
