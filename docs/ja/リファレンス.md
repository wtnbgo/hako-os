# hako リファレンス

[English](../en/reference.md)

**hako** は、OpenABL で起動できる Qualcomm 機で Debian trixie (arm64) を動かし、自前のアプリを展開する
ゲーム機向けの環境。今の対象機は Retroid Pocket Mini (V1, SM8250)。
機種に依存しない部分は `hako-*` パッケージ、機種固有の部分は `<機種>-bsp` パッケージ (今は `rpmini-bsp`) に分けている。
この文書は構成・パッケージ・設定・トラブル対処の詳細をまとめたもの。作業の流れは [README.md](README.md) の 1〜4 の文書を先に読む。

2026-11-20 時点の状態。

---

## 1. 全体の構成

```
 Windows PC                                              Retroid Pocket Mini (V1)
 ┌──────────────────────────────────────────┐            ┌──────────────────────────────┐
 │ ビルド用 Linux (Debian trixie。WSL2 も可) │            │ UFS 内蔵: Android (まだ残置)  │
 │  ~/hako-os  … この git リポジトリ         │            │   abl_a/b = OpenABL v1.2      │
 │   kernel/   → linux-image .deb            │            │                              │
 │   packages/ → hako-* / rpmini-bsp         │            │ microSD: dev イメージ         │
 │   repo/     … reprepro (apt リポジトリ)    │  USB-C 直結 │   ESP   (起動エントリ・Image) │
 │   elbe/     … イメージ定義 XML             │◀──────────▶│   rootA (Debian, rw)         │
 │                                           │ NCM + ACM  │   data                       │
 │  ELBE initvm (libvirt/KVM の VM)          │            │                              │
 │   └ XML から arm64 イメージを組み立てる    │            │ 192.168.7.2 (usb0)           │
 └──────────────────────────────────────────┘            └──────────────────────────────┘
```

- **方針**: 実機に入るものはすべて .deb にする。イメージは ELBE で毎回、最小構成から組み立てる。
  開発中は、イメージを作り直さずに apt で実機を更新する。
- **起動**: 電源 → Qualcomm の XBL → **OpenABL** (ABL を差し替えたもの) → ESP の起動エントリ
  (`loader/entries/*.conf`、systemd-boot と同じ BLS 形式) → Linux。
  - 起動時に **音量 -** を押していると OpenABL のメニューが出る (起動元や機種の選択)。**音量 +** だと Android が起動する。
  - 何も押さなければ、SD の起動エントリから自動で起動する。

## 2. ビルド環境

| もの | 内容 | 備考 |
|---|---|---|
| ビルド用 Linux | Debian trixie (x86_64)。WSL2 でもよい (KVM が使えること) | arm64 の開発パッケージを multiarch で入れてクロスビルドする (`dpkg --add-architecture arm64`) |
| 必要なパッケージ | `build-essential crossbuild-essential-arm64 debhelper cmake pkgconf reprepro libxml2-utils elbe`、各 `debian/control` の Build-Depends の arm64 版 (`libsdl3-dev:arm64` など) | |
| ELBE | 15.9。initvm は `~/elbe/initvm` (初回 `cd ~/elbe && elbe initvm create`、30 分前後) | VM 名 `initvm` (libvirt)。KVM で動くこと (`virsh -c qemu:///system dumpxml initvm` が `<domain type='kvm'>`)。WSL2 は `.wslconfig` に `nestedVirtualization=true` |
| 実機ログイン用の鍵 | ビルド機の `~/.ssh/id_*.pub` (無ければ `ssh-keygen -t ed25519` で作る) | dev イメージの root に自動で登録される |
| サブモジュール | `git submodule update --init` | LÖVE と raylib の上流ソース |

## 3. リポジトリの中身

| パス | 役割 |
|---|---|
| `kernel/` | カーネルを .deb にする。kernel.org 7.2 + ROCKNIX の SM8250 パッチと DTS。詳細は `kernel/README.md` |
| `kernel/SOURCE.pin` | 使うソースの版 (ROCKNIX のコミット、カーネル版と sha256、linux-firmware のタグ、パッケージ版) |
| `kernel/config/*.config` | ROCKNIX の設定に重ねる差分 (Debian の initramfs 用、USB ガジェット用など) |
| `kernel/firmware-<SOC>.list` | カーネルに組み込むファームウェア (GPU、DSP など) |
| `packages/` | 自作パッケージのソース (下の表)。`hako-base` (hako-base / hako-session / hako-dev)、`hako-launcher`、`hako-sdl-hello`、`hako-love`、`hako-raylib-hello`、`hako-raylib-classics`、`hako-siv3d-games`、`hako-mesa`、`rpmini-bsp`、`rg55g1-bsp` |
| `packages/hako-love/love`、`packages/hako-raylib-hello/raylib` | LÖVE と raylib の上流ソース (git サブモジュール。版を固定)。取得は `git submodule update --init` |
| `samples/` | パッケージにしないサンプル (`/data/dev/apps/` に置いて動かす)。`love-hello/` は LÖVE の動作確認 |
| `repo/` | reprepro の apt リポジトリ。設定 (`conf/`) だけ git 管理で、中身は生成物 |
| `elbe/rpmini-dev.xml` | dev イメージの定義 (パッケージ一覧、パーティション、fstab、仕上げコマンド) |
| `scripts/` | ビルド・配布の各スクリプト (5 章) |
| `out/` | 生成物 (`out/kernel/`、`out/packages/`、`out/images/<種類>/`)。git 管理外 |
| `build/` | 作業用 (カーネルのソース展開先、ログ)。git 管理外 |

### 自作パッケージ

**rpmini-bsp**: Retroid Pocket Mini の機種対応 (`packages/rpmini-bsp/`)。リリースでも使う。別の機種に載せるときは、これに当たる `<機種>-bsp` を作る。

| 含むもの | 役割 |
|---|---|
| 依存関係 | カーネル、initramfs-tools、firmware-atheros / firmware-qcom-soc、alsa-ucm-conf |
| `/usr/sbin/rpmini-update-esp` | カーネルや initrd が更新されたら、Image・initrd・dtb を ESP にコピーし、起動エントリ `loader/entries/rpmini.conf` を書き直す (カーネルと initramfs のフックから自動で呼ばれる) |
| `/etc/default/rpmini-esp` | 上記の設定 (ESP の場所、dtb、カーネルの起動オプション) |
| `/usr/lib/rpmini/usb-gadget` と `rpmini-usb-gadget.service` | USB-C をデバイスモードにし、ネットワーク (NCM) とシリアル (ACM) を出す |
| `50-rpmini-usb0.network` | usb0 = 192.168.7.2/24。つないだ PC に DHCP でアドレスを配る |
| UCM (`ucm2/Qualcomm/sm8250/`) | 音声経路の設定。ROCKNIX 由来。スピーカーのハード音量 (デジタル -6dB) はここで決める |
| `51-rpmini.conf` (WirePlumber) | ソフト音量にする、出力を S16LE にする (q6 DSP で 24bit だと小さくなるため)、初期音量 |
| `/usr/lib/hako/hw/volume` | PipeWire がないときの音量ボタン (ハード音量を上下)。`/usr/lib/hako/volume` から呼ばれる |
| `70-rpmini-gamepad.rules` | 内蔵パッドをジョイスティックとして扱わせる (udev がマウスと誤判定するため) |
| `71-rpmini-wcd938x-nosleep.rules` | ヘッドホン用チップ (WCD938x) の省電力を止める。止めないとジャックが検出されない |
| `72-rpmini-touch-rotate.rules` | cage の回転に合わせてタッチ座標を回す (libinput の補正行列) |
| `/usr/lib/hako/session.d/10-rpmini.sh` | セッションの機種既定値: `HAKO_ROTATE=270` (縦長パネル)、内蔵パッドの `SDL_GAMECONTROLLERTYPE` / `SDL_GAMECONTROLLERCONFIG` |

**hako-base**: 機種によらない土台 (`packages/hako-base/`)。リリースでも使う。hako-session が依存する。

| 含むもの | 役割 |
|---|---|
| `/usr/lib/hako/rtc-offset` と `hako-rtc-offset.service` (`-save.timer` / `-save.path`) | Linux から時刻を書けない RTC の機種 (RG 55G1 の PMIC の RTC) で時計を保つ。「時刻 − RTC」を `/var/lib/hako/rtc-offset` に保存し (NTP で同期した直後、1 時間ごと、終了時)、起動の早い段階で「RTC + 差分」に戻す。RTC が時刻を保てる機種 (Retroid Pocket Mini) では何もしない。NTP は依存する `systemd-timesyncd` |
| `/usr/lib/hako/grow-data` と `hako-grow-data.service` | 初回起動時に、ラベル `data` のパーティションをディスクの最後まで広げる (`sgdisk -e` → `growpart` → `resize2fs`)。終わると `/var/lib/hako-base/grow-data.done` を作り、以後は動かない。インストール時には動かさない |

**hako-dev**: 開発用 (`packages/hako-base/`)。リリースには入れない。

| 含むもの | 役割 |
|---|---|
| 依存関係 | ssh サーバ、gdbserver、strace、evtest、alsa-utils、iwd、mesa (GL/Vulkan)、kmscube、vulkan-tools、libsdl3、grim など |
| ttyGS0 の自動ログイン | USB シリアルから root で即ログイン |
| `60-hako-wlan.network` | Wi-Fi を DHCP で使う |
| `/etc/hako/session.d/90-dev-override.sh` | `/data/dev/session.env` があれば読み込む (起動するアプリの差し替え用。リリースには入らない) |
| `hako-dev.conf` (tmpfiles) | `/data/dev` と `/data/dev/apps` を作る |

**hako-session**: 起動時にアプリを全画面で自動起動する (`packages/hako-base/`)。リリースでも使う。

| 含むもの | 役割 |
|---|---|
| `hako-session.service` | tty1 で、一般ユーザー `hako` として `session-run` を起動する。終了したら 1 秒後に再起動する (60 秒で 10 回まで)。tty1 の getty とは排他 |
| 起動スプラッシュ | Plymouth のテーマ `hako` (`/usr/share/plymouth/themes/hako/`。画像は `packages/hako-base/splash/make-images.py` で作る)。initramfs にも入る (hako-session の postinst がテーマを選んで initramfs を作り直す)。カーネル引数は bsp が付ける: `quiet splash loglevel=3 logo.nologo vt.global_cursor_default=0`。hako-session は plymouth-quit より先に `plymouth quit --retain-splash` を実行し、`TTYReset=no` にしている (リセットすると tty1 がテキストのモードに戻る) ので、スプラッシュとランチャーの間にコンソールが出ない。ログは `journalctl -b`。画面に出したいときは `/etc/default/<機種>-esp` の `CMDLINE` から `quiet splash` を外して `<機種>-update-esp` |
| `/usr/lib/hako/session-run` | 環境設定を読み込み、cage の中でアプリを起動する (`HAKO_COMPOSITOR` が空なら直接 `exec`) |
| `/usr/lib/hako/session-app` | cage の中で `wlr-randr` で出力を回し、`SDL_VIDEO_DRIVER=wayland` でアプリを起動する |
| 環境設定 | 順に読み込む: `/usr/lib/hako/session.d/*.sh` (機種の既定値。bsp が入れる) → `/etc/default/hako-session` (`HAKO_COMPOSITOR=cage`、`SIV3D_FULLSCREEN`、`HAKO_APP`、`HAKO_APP_ARGS` など) → `/etc/hako/session.d/*.sh` (追加分) |
| `/usr/lib/hako/volume` と triggerhappy の設定 | 音量ボタン → PipeWire の音量を 5% ずつ上下 (PipeWire がなければ機種の `/usr/lib/hako/hw/volume`)。triggerhappy は root で動かす (`triggerhappy.service.d/hako.conf`) |
| sysusers / tmpfiles | ユーザー `hako` (グループ video/render/input/audio、ホーム `/var/lib/hako`) |

- 起動するアプリは `/usr/bin/hako-app`。Debian の alternatives で、アプリのパッケージが postinst で自分を登録する
  (`update-alternatives --install /usr/bin/hako-app hako-app /usr/bin/<アプリ> <優先度>`)。優先度が一番高いものが選ばれる。
- PAM (`PAMName=login`) で logind のセッションを作るので、root でなくても画面と入力デバイスを使える (uaccess)。`XDG_RUNTIME_DIR` も設定される。
- 標準では `hako-launcher` (下記) が `hako-app` になり、各アプリはランチャーから起動する。
  ランチャー自体が終了した場合は、すぐ再起動される。

バージョンは各ソースの `debian/changelog` の先頭で決まる (hako-session と hako-dev は `packages/hako-base/` で同じ版)。
旧名 (rpmini-session / rpmini-dev / rpmini-launcher / rpmini-sdl-hello) は Conflicts / Replaces で置き換わる。

**hako-sdl-hello**: SDL3 のサンプル (`packages/hako-sdl-hello/`)。アプリを作るときのひな形。

- C 1 ファイル (`src/main.c`) + Makefile + debian/。PC で arm64 向けにクロスビルドする (`build-packages.sh` は全パッケージを `-a arm64` でビルドする)。
- 1280x960 の横向きキャンバスに描く。標準 (cage の中) では回転済みの横長画面にそのまま出す。cage なしで KMSDRM に直接描くときは、自分で縦長のパネルへ 90 度回転して表示する (`HAKO_ROTATE` / `--rotate`)。
- パッド (Switch 配置のボタン名)・タッチ・FPS を表示する。Start + Select の長押しで終了。
  ABXY の図は位置どおりに描く (`HAKO_PAD_LAYOUT=label` のときは刻印に合わせて並べ替える。6 章「SDL3 とパッド」)。
- `hako-sdl-hello [--rotate 0|90|180|270] [--seconds N] [--shot file.bmp]`。`--shot` で画面を BMP に保存できる (遠隔で描画を確認するとき用)。
- ssh から動かすときは `systemd-run --unit=sdl-hello --collect hako-sdl-hello` を使うと、ssh を切っても動き続ける。ログは `journalctl -u sdl-hello`。
- ランチャー用の `/usr/share/hako/apps/hako-sdl-hello.app` を入れる (アプリのパッケージの見本)。

**hako-love**: LÖVE 12 (Lua のゲームフレームワーク、SDL3 版) (`packages/hako-love/`)。

- Debian の `love` は 11.x (SDL2) なので、上流の開発版 (main、12.0) をサブモジュールで固定してビルドする。
  手を入れていないので fork はしていない (修正が要るようになったら fork してサブモジュールの参照先を替える)。
- 依存ライブラリ (SDL3、LuaJIT、freetype、harfbuzz、OpenAL、modplug、theora、vorbis) は Debian のものを使う。
  ビルドは他と同じ arm64 クロスビルド (cmake。7 分ほど)。`/usr/bin/love` と `liblove-12.0.so` を入れる。Debian の `love` とは排他。
- 上流を進めるときは、サブモジュールのコミットを替えて `debian/changelog` の版 (`12.0~git<日付>.<コミット>-1`) を上げる。
- 描画は Vulkan (Turnip) が選ばれる。`LOVE_GRAPHICS_USE_OPENGLES=1` や `love.conf` の `t.graphics.renderers` で変えられる。
- ゲームは `.app` で `Exec=/usr/bin/love`、`Args=<ゲームのフォルダか .love>` として登録する (`samples/love-hello/love-hello.app` が見本)。

**hako-raylib-hello**: raylib (C のゲームライブラリ) の SDL3 版サンプル (`packages/hako-raylib-hello/`)。

- raylib は上流のリリース (6.2) をサブモジュール `raylib/` で固定し、サンプルに静的に組み込む (`PLATFORM=SDL`。SDL3 は Debian の
  ものを `find_package` で使う)。実行時の依存は libsdl3 だけ。音は raylib 自身の miniaudio で ALSA → PipeWire に出す。
- 描画は OpenGL 4.6 (freedreno)。1280x960、60fps。
- 3D シーン: 左スティック/十字キーで移動、下ボタンでジャンプ、右スティックでカメラ、L2/R2 でズーム。ABXY の図 (位置どおり、
  `HAKO_PAD_LAYOUT=label` にも対応)、スティック、タッチ、FPS を表示。ABXY で音。START+SELECT で終了。
- raylib のボタン名 (`GAMEPAD_BUTTON_RIGHT_FACE_DOWN` など) も SDL と同じく位置。
- raylib を静的に組み込むので、raylib のライセンスと、raylib が組み込む外部ライブラリ (stb、miniaudio など) の告知を
  `/usr/share/doc/hako-raylib-hello/licenses/` に入れる。元は `licenses/` (`make-licenses.py` でサブモジュールから作る。hako-raylib-classics も使う)。
- 実機で確認済み (2026-11-20): 移動・ジャンプ・カメラ・ズーム・音・タッチ・終了。

**hako-raylib-classics**: raylib の古典ゲーム 12 本 (raysan5/raylib-games の classics、zlib) をまとめたアプリ (`packages/hako-raylib-classics/`)。

- 元のソース (`classics/`) は変えずに、`src/games/` のラッパーから取り込む (`src/hk.h` のマクロで `main()`・描画・入力を差し替える)。
  各ゲームは元の大きさ (800x450 など) でレンダーテクスチャに描き、画面に合わせて拡大する。
- 入力 (`src/hk_input.c`): 矢印キー = 十字キー / スティック / 画面の十字キー、Space・Enter = A、P = START。マウスのゲームはタッチがマウス、スティックでポインター。
- `/usr/lib/hako/raylib-classics/` に入り、`licenses/` (ゲーム、raylib、raylib が組み込む外部ライブラリの告知) をメニューから読める。
- raylib は `hako-raylib-hello` のサブモジュールを共有して静的に組み込む。

**hako-siv3d-games**: Siv3D のサンプル「ゲーム」22 本をまとめたアプリ (`packages/hako-siv3d-games/`)。

- SDL3 版 OpenSiv3D (wtnbgo/OpenSiv3D `develop_sdl3`、`siv3d-app.json` で commit を固定) で、`siv3d_app.py --target rpmini stage` によりビルドする
  (docker と deckbuild-rpmini のイメージが要る)。`/usr/lib/hako/siv3d-games/` に、実行ファイル・SDL3・Siv3D のリソース一式が入る (47 MB)。
- 入力は `src/Input.hpp` (パッド・キーボード・マウス・タッチ。A / B は刻印どおり)。メニュー、各ゲームの操作説明、ライセンスの画面を持つ。
- 1〜12・21・22 は Siv3D のドキュメントのサンプル (MIT)、13〜20 は Siv3D-Samples と Reputeless/games (CC0)。各ファイルの先頭に出どころと変更点。
- Cookie Clicker の進み具合は `~/.local/share/hako-siv3d-games/` (ユーザー hako) に保存する。

**hako-mesa**: Adreno 613 (RG 55G1) に対応した Mesa (`packages/hako-mesa/`)。

- Debian の Mesa (trixie の 25.0、backports の 26.1) は Adreno 613 を知らない (Mesa 26.2 で対応)。Debian の Mesa の元 tarball 26.2.6 (版と sha256 を固定) から、
  freedreno (GL / GLES / EGL / GBM) と turnip (Vulkan) だけを LLVM なしでクロスビルドする。
- `/usr/lib/hako/mesa` に入り、Debian の Mesa は置き換えない。`/usr/lib/hako/mesa/env.sh` (LD_LIBRARY_PATH、glvnd の EGL vendor、Vulkan ICD) を
  読み込んだプログラムだけが使う。rg55g1-bsp のセッションの既定がこれを読む。Debian の Mesa が 26.2 以上になったら外す。

**hako-launcher**: アプリの一覧から起動するランチャー兼システム設定 (`packages/hako-launcher/`)。リリースでも使う。

- C + SDL3 (SDL3_ttf / SDL3_image)。`src/` は main (画面と入力)、apps (`.app` の読み込みと起動)、sys (音量・明るさ・電源・情報)、i18n (日本語/英語)、ui (文字描画)。
- postinst で `hako-app` の alternative に優先度 50 で登録する。
- アプリタブ: 登録されたアプリを 3x3 のタイルで並べる。A (またはタップ) で起動し、ランチャーは画面と音を閉じて終了を待つ。
  アプリが終わると一覧に戻る (エラー終了・異常終了はメッセージを出す)。
- **HOME ボタン長押し (1 秒)** で、起動中のアプリを終了させて戻る。triggerhappy (`/etc/triggerhappy/triggers.d/hako-home.conf`) が
  `/usr/lib/hako/home-button` を呼び、ランチャーに SIGUSR1 を送る。ランチャーはアプリのプロセスグループに SIGTERM、3 秒後に SIGKILL。
- **電源ボタン**: 短く押すとスリープ (s2idle)、もう一度押すと復帰。5 秒の長押しで電源断。
  短押しは `hako-screen-idle` が受け持ち、復帰させた押下は捨てる (logind には復帰直後に届いてしまうため)。
  logind は長押しだけを扱う (`/usr/lib/systemd/logind.conf.d/50-hako-power-key.conf`)。無操作で画面が消えているときは点灯だけ。
  **スリープは気休め程度。電池を持たせたいときはシャットダウンする。** CPU とアプリは止まるが、SoC は深い省電力状態に
  入らない (4 章の表の「スリープ」)。
- 設定タブ: 音量 (変えると試し音が鳴る)、画面の明るさ (logind の `SetBrightness`)、画面を消すまで (`~/.config/hako/screen-off`、分、0 は消さない。`hako-screen-idle.service` が root で全入力機器を見張り、`bl_power` でパネルのバックライトを消す。消えている間は入力機器を横取りするので、点けるための入力は電源ボタンも含めてほかへ届かない)、言語、タイムゾーン (systemd-timedated)、外部モニターの音声 (`~/.config/hako/external-audio`、`/usr/lib/hako/audio-route` が反映)、Bluetooth (専用の画面。オン/オフ、機器を探す、ペアリングと接続、切断、X で登録を解除。BlueZ と D-Bus で話し、ペアリングの応答役も持つ)、
  システム情報、再起動、電源を切る (電源とタイムゾーンは polkit ルール `50-hako-launcher.rules` でユーザー `hako` に許可)。
  起動するアプリにはタイムゾーンを `TZ` で渡す。
- 外からの起動: `/usr/lib/hako/launch-app <id>` (root で実行) で、登録済みのアプリをランチャーに起動させる。
  動いているアプリがあれば閉じてから起動する。開発ツールが転送後に使う (中身は `$XDG_RUNTIME_DIR/hako-launch` に id を書いて SIGUSR2)。
- 操作: 十字キー/左スティックで選択、A で決定、B で戻る、L/R でタブ切り替え。タッチも使える。
- 言語: 日本語と英語。設定で選んだ値は `/var/lib/hako/.config/hako/language` に保存する。未設定なら
  `/etc/default/hako-session` の `HAKO_LANGUAGE`、それも無ければ日本語。起動するアプリには `HAKO_LANGUAGE=ja|en`、`LANGUAGE`、`LANG` を渡す。

**`.app` ファイル** (アプリの登録): `/usr/share/hako/apps/*.app` (パッケージが入れる) と `/data/dev/apps/*.app` (開発用。タイルに「開発」と出る) を読む。

```ini
# 表示名 (必須)
Name=SDL3 サンプル
# 言語ごとの表示名 (Description も同様)
Name[en]=SDL3 Sample
Description=パッド・タッチ・音の確認
# 実行ファイル (必須。.app からの相対パスも可。実行できなければ一覧に出ない)
Exec=/usr/bin/hako-sdl-hello
# 引数 (空白区切り)
Args=/data/dev/x/data -fullscreen=yes
# 作業ディレクトリ (省略時は Exec のディレクトリ)
Dir=/data/dev/x
# タイルのアイコン (PNG など)
Icon=icon.png
# 環境変数 (複数行可)
Env=FOO=1
# 並び順 (小さいほど先。同じなら名前順)
Order=10
```

`#` のコメントは行の先頭にだけ書ける (値の後ろに書くと値の一部になる)。

## 5. よく使う操作

コマンドはすべて WSL の `~/hako-os` で実行する。

### 実機につなぐ

1. 実機を USB-C で **PC に直結**する。ハブ経由だと USB のデバイスモードにならないことがあった。
2. WSL から ssh する (鍵は WSL 側にあるので、Windows の ssh では入れない)。

```bash
ssh root@192.168.7.2
```

- PC 側には 192.168.7.x のアドレスが自動で付く (Windows の標準ドライバで認識する)。
- シリアルも出ている (実機側は ttyGS0 で root 自動ログイン)。Windows では標準ドライバで
  「USB シリアル デバイス (COMn)」として見える (デバイスマネージャーの「ポート」、ハードウェア ID は `VID_1D6B&PID_0104&MI_02`)。
  115200bps で開くと root のシェルになる (Tera Term、PuTTY など)。ネットワークが動かないときの予備。
- Bluetooth の機器のペアリングを ssh からする場合 (機器をペアリング状態にしてから):
  ```sh
  bluetoothctl --timeout 10 scan on              # 機器を見つける
  bluetoothctl devices                           # 名前でアドレスを確かめる
  printf "agent NoInputNoOutput\ndefault-agent\npair <MAC>\n" | bluetoothctl   # 応答役 (agent) を付けてペアリング
  bluetoothctl trust <MAC>; bluetoothctl connect <MAC>
  ```
  `trust` しておくと、次回からは機器のボタンを押すだけで自動でつながる。
- Wi-Fi を使う場合は、実機で `iwctl station wlan0 connect <SSID>` を実行する。

### 実機のソフトを更新する (普段の開発)

```bash
bash scripts/dev-update.sh                     # 自作パッケージで、実機に入っているものを全部最新に
bash scripts/dev-update.sh --build             # パッケージをビルドしてから更新
bash scripts/dev-update.sh <pkg>...            # 指定したパッケージを入れる/更新する
bash scripts/dev-update.sh --reinstall <pkg>   # 同じバージョンでも入れ直す
HAKO_DEV=root@<IP> bash scripts/dev-update.sh   # 接続先を変える (Wi-Fi 経由など)
```

- 仕組み: `repo/` を WSL の 127.0.0.1:8780 で配信し、`ssh -R` で実機の 127.0.0.1:8780 に見せる。そのための apt ソース (`/etc/apt/sources.list.d/hako-dev-tunnel.list`) は実行中だけ置く。
  同じ ssh で逆 SOCKS プロキシ (`-R 1080`) も張るので、Debian 公式の依存も PC 経由で取れる (実機の Wi-Fi は不要)。
- apt は**同じバージョンを入れ直さない**。パッケージを変えたら changelog でバージョンを上げる (試すだけなら `--reinstall`)。

### 自動起動するアプリを扱う

```bash
systemctl stop hako-session            # 止める (手で実行して試すとき)。再起動すれば元に戻る
systemctl restart hako-session         # 起動し直す
journalctl -u hako-session -f          # アプリの出力を見る
update-alternatives --config hako-app  # 登録済みのアプリから選ぶ
```

パッケージにせずにアプリを試す場合 (rsync で速く回す)。ランチャーに登録するのが基本:

```bash
# PC から
rsync -av build/mygame root@192.168.7.2:/data/dev/
# 実機で (ランチャーはアプリタブを開くたびではなく、起動時とアプリ終了時に .app を読み直す)
mkdir -p /data/dev/apps
printf 'Name=mygame\nExec=/data/dev/mygame/mygame\n' > /data/dev/apps/mygame.app
/usr/lib/hako/launch-app mygame        # すぐ起動する (動いているアプリは閉じる)
```

ランチャーを通さずにセッションのアプリそのものを差し替えたいときは、`/data/dev/session.env` に
`HAKO_APP=/data/dev/mygame/mygame` (`HAKO_APP_ARGS=...` も書ける) を書いて `systemctl restart hako-session`。
消せば元の `/usr/bin/hako-app` に戻る。アプリは一般ユーザー `hako` で動くので、
`/data/dev/` 以下のファイルはそのユーザーが読めるようにしておく。

ランチャーの画面を PC から確認する: `runuser -u hako -- env XDG_RUNTIME_DIR=/run/user/$(id -u hako) WAYLAND_DISPLAY=wayland-0 grim -s 0.5 /tmp/x.png`
ランチャーとアプリのログは `journalctl _UID=$(id -u hako)`。

### 自作パッケージをビルドする

```bash
bash scripts/build-packages.sh     # changelog の版がまだビルドされていない packages/*/ だけ → out/packages/
bash scripts/build-packages.sh hako-love   # 指定したものは必ずビルドする
FORCE=1 bash scripts/build-packages.sh     # 全部ビルドし直す
bash scripts/publish-repo.sh       # out/kernel と out/packages を repo/ に登録
```

パッケージは changelog の版で見分ける。版を上げないと前のビルドがそのまま使われる。ビルドし直したパッケージの古い .deb は消える。
`dev-update.sh` と `build-image.sh` は、`publish-repo.sh` を自動で呼ぶ。

### カーネルをビルドする

```bash
kernel/build.sh            # → out/kernel/linux-image-7.2.0-rpmini_<版>_arm64.deb など
kernel/build.sh prepare    # パッチ適用と設定まで (パッチが当たらないときの確認用)
```

- 同じカーネル版で作り直すときは、`kernel/soc/<SOC>.conf` の `KERNEL_PKGREV` を上げる (上げないと apt が更新しない)。
- 実機への反映は `bash scripts/dev-update.sh linux-image-7.2.0-rpmini`。`rpmini-update-esp` が ESP を自動で書き換えるので、再起動すれば新しいカーネルで起動する。
- 新しいカーネルで起動しなくなったときは、SD を PC で読み、ESP の `rpmini/Image` を戻す (または dev イメージを書き直す)。

### イメージを作って SD に書く

```bash
bash scripts/build-image.sh dev    # → out/images/dev/rpmini-dev.img (7GiB)。KVM で 15〜20 分ほど
```

- 版が変わった自作パッケージのビルド、repo への登録、検査、ssh 鍵の埋め込み、initvm でのビルドまでを一括で行う。
- ELBE のビルドの前に、最後まで行かないと分からない誤りを検査して止める: XML の書式の誤り、localhost の apt ソースを
  含むパッケージ、pkg-list にあるのに `repo/` に無い hako / 機種のパッケージ。
- initvm は KVM で動かすこと (`virsh -c qemu:///system dumpxml initvm` が `<domain type='kvm'>`)。KVM が無いと数時間かかる。
- 書き込みは balenaEtcher や `dd` などで行う。WSL の場合、イメージは `\\wsl.localhost\<ディストリ名>\...` から見えるが、
  Windows 側のドライブにコピーしてから書くほうが速くて確実。
- **ビルド中は `build-packages.sh` / `publish-repo.sh` / `dev-update.sh` を動かさない。** ELBE はビルドの間ずっと
  `repo/` を読むので、途中で古い版の .deb が消えると `AptCacheUpdateError` で失敗する。
- **イメージを作り直すのは、ベース構成を変えたとき (XML のパッケージ一覧やパーティション) と、配布用を固めるときだけ**。普段は `dev-update.sh` で済む。

## 6. 実機での確認コマンド

```bash
# 画面と GPU
kmscube                                   # 回転する立方体 (Ctrl+C で終了)
vulkaninfo --summary

# 音 (PipeWire はセッションのユーザー hako で動いている。root からは次のように呼ぶ)
U="runuser -u hako -- env XDG_RUNTIME_DIR=/run/user/$(id -u hako)"
$U wpctl status                           # 出力先 (Speaker / Headphones) と音量
$U wpctl set-volume @DEFAULT_AUDIO_SINK@ 0.7
$U speaker-test -D default -c 2 -t sine -f 440 -l 1

# パッド・ボタン (セッションのアプリがパッドを掴んでいるので、先に止める)
systemctl stop hako-session; evtest; systemctl start hako-session

# Wi-Fi
iwctl station wlan0 scan; iwctl station wlan0 get-networks

# 全体の状態
systemctl --failed; dmesg --level=err,warn
```

### 音声の構成

- セッション (ユーザー hako) の中で PipeWire + WirePlumber が動く。アプリは SDL3 から PipeWire に出す
  (ALSA の `default` も pipewire-alsa 経由で PipeWire に行く)。
- 出力は「Speaker」と「Headphones」の 2 つ。ヘッドホンを挿すと自動で切り替わり、音量は出力ごとに記憶される。
- WirePlumber の設定 `/usr/share/wireplumber/wireplumber.conf.d/51-rpmini.conf` (rpmini-bsp) の要点:
  - **16 ビット (S16LE) 固定**。この DSP は 24 ビット (S24_LE) を受け付けるが、約 -48dB とほぼ無音になる。
  - **ハード音量は固定** (soft-mixer)。スピーカーは UCM でデジタル -6dB、有効化のたびに標準設定がアンプを +12dB にするので、
    100% = +6dB。それより下は PipeWire のソフト音量。初期値 70%。
- ALSA に直接出す場合 (PipeWire を止めたとき) は、`alsaucm -c RetroidPocket set _verb HiFi set _enadev Speaker` で経路を有効にし、
  `plughw:0,1` に 16 ビットで出す。

### SDL3 とパッド

機種の既定値 (`/usr/lib/hako/session.d/10-rpmini.sh`、rpmini-bsp) で、次の 2 つを SDL に渡している。アプリ側の設定は不要。

- `SDL_GAMECONTROLLERCONFIG`: 内蔵パッドのボタン割り当て。SDL の自動割り当ては、カーネルの `BTN_NORTH` (上) を旧名の
  `BTN_X` として「X = 左」と扱い、上と左が逆になるため、正しい割り当てを明示している。
- `SDL_GAMECONTROLLERTYPE=0x2020/0x3001=SwitchPro`: ボタンの刻印を Switch 配置 (下 = B、右 = A、左 = Y、上 = X) と SDL に教える
  (`SDL_GetGamepadButtonLabel` が刻印を返す)。

**ABXY は位置か刻印か** (`HAKO_PAD_LAYOUT`、`/etc/default/hako-session`):

- SDL3 の a/b/x/y (`SDL_GAMEPAD_BUTTON_SOUTH/EAST/WEST/NORTH`) は刻印ではなく位置 (下/右/左/上。Xbox の呼び名)。
  任天堂配置の本機では、刻印と名前が逆になる (下のボタンが a、刻印は B)。これは SDL の仕様。
- `position` (既定): SDL の仕様のまま。下ボタンを決定にする Xbox 前提のゲームや、パッドの図を描くアプリがそのまま正しく動く。
- `label`: session-run が割り当ての a↔b、x↔y を入れ替え、`face:abxy` を足す。a/b/x/y の名前が刻印どおりになる
  (任天堂系の操作感)。代わりに SOUTH などが位置を表さなくなるので、位置を前提にしたアプリ (図を描く、下ボタン = 決定) はずれる。
  入れ替えるのは `SDL_GAMECONTROLLERCONFIG` にある割り当て (内蔵パッド) だけ。外付けのパッドは SDL の組み込み割り当てのまま。
- cage はパッドを扱わない (アプリの SDL が入力デバイスを直接読む) ので、コンポジタ側では入れ替えられない。
- ランチャーは刻印で判定する (A = 決定、B = 戻る) ので、どちらでも同じ。アプリで刻印を表示したいときは
  `SDL_GetGamepadButtonLabel` を使う (LÖVE は Lua から呼べないので、`getGamepadType()` と `HAKO_PAD_LAYOUT` を見て読み替える。`samples/love-hello` 参照)。
- 実機で確認済み (2026-11-20): position / label とも、ランチャー・SDL3 サンプル (図も)・LÖVE サンプルで刻印・位置が想定どおり。

セッション外 (ssh から手で起動) でアプリを試すときは、`set -a; for f in /usr/lib/hako/session.d/*.sh /etc/default/hako-session; do . $f; done; set +a`
してから起動するとほぼ同じ条件になる (`HAKO_PAD_LAYOUT` の入れ替えは session-run がするので、この方法では効かない)。

## 7. トラブル時

### WSL のディスクが壊れた

- 症状: ビルドが止まる、`database disk image is malformed`、Python の `bad marshal data` など。
- 確認: `sudo dmesg | grep EXT4-fs` で `Remounting filesystem read-only` が出ていないか見る。
- 復旧の流れ:
  1. 壊れたディストリを止め、別のディストリから ext4.vhdx をつないで `e2fsck` をかける。
  2. `debsums -a -c` と `dpkg --audit` で壊れたパッケージを探し、`apt-get install --reinstall` で入れ直す。
  3. initvm が壊れていたら作り直す (下記)。
- 原因は WSL の強制終了と思われる。ビルド中に `wsl --shutdown` や PC のスリープをしない。

### ELBE

- initvm を作り直す: `virsh -c qemu:///system destroy initvm; virsh -c qemu:///system undefine initvm`、
  `~/elbe/initvm` を退避してから、`cd ~/elbe && elbe initvm create` (30 分前後)。
- 失敗したプロジェクトが残ったら、`elbe control list_projects` で確認し、`elbe control del_project <パス>` で消す。
- `elbe validate` は `<repodir>` と `<archivedir>` を誤りと報告するが、submit 時に展開されるので問題ない。
- `no libvirt domain "initvm"`: libvirt が定義を忘れている (WSL の再起動後など)。initvm 自体は残っているので
  `virsh -c qemu:///system define ~/elbe/initvm/libvirt.xml` で登録し直せばよい。
- XML の `revision` は ELBE のスキーマの版 (最大 6) で、イメージの版ではない。上げると検証で落ちる。

### 実機

- **ssh に入れない**: USB を直結しているか確認する。だめならシリアル (COM ポート) から入る。それでもだめなら、SD を PC で読んでログを見る。
- **パッケージ更新中に接続が切れた**: 実機で `dpkg --configure -a` を実行してから `dev-update.sh` をやり直す。
  なお、USB ガジェットのサービスは更新時に再起動しない設定にしてある (再起動すると USB の接続が切れるため)。
- **Android に戻したい**: 起動時に音量 + で Android が起動する (内蔵の Android はまだ残っている)。
  OpenABL 自体を純正に戻すには、EDL で `tools/edl/hako_edl.py <機種> restore <バックアップ>` を実行する
  (導入前に取ったバックアップの `abl_a` / `abl_b` を書き戻す。[1-実機の準備.md](1-実機の準備.md) の「元に戻す」)。

### 「Run Script as Root」(Android) の癖

- スクリプトを 1 行ずつ別コマンドとして送るので、**`sh /data/media/0/hako/<スクリプト>.sh [引数] [> ログ]` だけの 1 行**にして、本体を呼ぶ。
- root が書いたファイルが、PC (adb / MTP) からは古い内容のまま見えることがある。新しい名前のフォルダに書くか、`log -t rpmini` で logcat に出す。

## 7.5 ゲームエンジン (吉里吉里Z / Siv3D) を載せる

どちらも SDL3 版を arm64 Linux 向けに別途ビルドし、実機の `/data/dev/<アプリ>/` に置いて `.app` で登録する
(パッケージにする前の開発モード)。ビルド環境はエンジンごとに用意する (Debian trixie + aarch64 クロスコンパイラ +
arm64 の開発ライブラリを入れたコンテナなど)。

### 吉里吉里Z のタイトルを実機で動かす (開発モード)

未パックのデータで動かす。実行ファイルの隣にゲームデータを置く。

```bash
rsync -a <ビルド出力>/ root@192.168.7.2:/data/dev/<title>/          # krkrz 本体と同梱の libSDL3
rsync -a <タイトル>/data/ root@192.168.7.2:/data/dev/<title>/data/
# 実機: ランチャーに登録 (アプリ終了時に一覧へ反映される。すぐ出したいときは systemctl restart hako-session)
printf 'Name=<title>\nExec=/data/dev/<title>/<実行ファイル>\nArgs=/data/dev/<title>/data -fullscreen=yes\n' > /data/dev/apps/<title>.app
```

### Siv3D のアプリを実機で動かす

ビルドしたアプリ一式を `/data/dev/<exeName>/` に転送し、`/data/dev/apps/<exeName>.app` を書いて
`/usr/lib/hako/launch-app <exeName>` で起動する。Siv3D はアセットを作業ディレクトリからの相対パスで読むので、
`.app` の `Dir=` (省略時は Exec のディレクトリ) をアプリのフォルダにする。

### 画面の向き (縦長パネル) とコンポジタ

パネルは本来縦長 (960x1280)。KMS/DRM に直接描くとアプリは縦長の画面を受け取り、横長のゲームは小さく
表示される (krkrz・Siv3D とも回転の仕組みを持たない)。

- **標準はコンポジタ方式** (rpmini-bsp 0.1.11 から。`/etc/default/hako-session` の `HAKO_COMPOSITOR=cage`):
  キオスク用コンポジタ cage の中で、`wlr-randr` で出力を `HAKO_ROTATE` 度 (Retroid Pocket Mini は 270。90 だと上下逆。
  機種の既定値は bsp の `/usr/lib/hako/session.d/10-rpmini.sh`、変えるなら `/etc/default/hako-session`) 回すので、アプリには 1280x960 の横長画面に見える。
  タッチ座標は cage が変換しないので、libinput の補正行列で回す (`/usr/lib/udev/rules.d/72-rpmini-touch-rotate.rules`。
  `HAKO_ROTATE` を変えるときはこの行列も合わせる。270 度で四隅が指の位置に合うことを実機で確認済み)。アプリは Wayland で動く (SDL は `WAYLAND_DISPLAY` があれば Wayland を選ぶ)。
  アプリには `HAKO_ROTATE=0` が渡る (回転済みなので、アプリ側でもう一度回さないこと)。
- cage を使わず KMS/DRM に直接描くには、`/data/dev/session.env` などで `HAKO_COMPOSITOR=` (空) にする。
- 試した結果: SDL サンプル・krkrz・Siv3D とも横向きで表示。sdl-hello は 60fps。音声 (PipeWire) も OK。
- 全画面: 起動時に全画面にすると、エンジンがゲーム画面を比率を保って 1280x960 に拡大する (16:9 は上下に黒帯)。
  - 吉里吉里Z: 起動オプション `-fullscreen=yes` (最初に表示するウィンドウを全画面にする)。
    例: `HAKO_APP_ARGS="/data/dev/<title>/data -fullscreen=yes"`。
  - Siv3D: 環境変数 `SIV3D_FULLSCREEN=1` (SDL3 版 Siv3D が対応)。`/etc/default/hako-session` で既定で有効。
  - 確認済み: krkrz 本体のコアデモ、Siv3D のひな形アプリ、Siv3D ゲーム集 (`hako-siv3d-games`、22 本)。KAG 系のゲームデータは Linux での動作確認自体がまだなので別途。
- 画面の確認: `runuser -u hako -- env XDG_RUNTIME_DIR=/run/user/$(id -u hako) WAYLAND_DISPLAY=wayland-0 grim /tmp/s.png`

### 開発ループとデバッグ

- 高速ループ: ビルド → `rsync` で `/data/dev/<app>/` → `/data/dev/apps/<app>.app` で登録 → ランチャーから起動。
  HOME 長押しで終了して一覧に戻る。開発ツールから使うときは、転送 → `.app` を書く → `launch-app <id>` までを
  1 コマンドにまとめておくと速い。
- ログ: アプリの出力は `journalctl -u hako-session` には出ない (ユーザーセッション扱い)。
  `journalctl -b SYSLOG_IDENTIFIER=session-run` または `journalctl _PID=<pid>` で見る。
- リモートデバッグ: 実機で `gdbserver :2345 ./MyApp`、WSL で `gdb-multiarch` → `set sysroot target:` →
  `target remote 192.168.7.2:2345`。ソースレベルで追うには Debug / RelWithDebInfo でビルドする。
- krkrz の自動操作・画面確認: `-replfile=<dir>` の REPL チャネルで TJS を送り、`Agent.captureScreen()` で PNG 保存
  (KMS/DRM 直描画でもキャプチャできる)。
